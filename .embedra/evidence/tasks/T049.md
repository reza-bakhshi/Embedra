# T049 Evidence — STM32MP/heterogeneous parts as distinct providers

## Status

`COMPLETE` on 2026-10-02. T049 researches and implements dedicated STM32MP heterogeneous
target providers under the `targets/stm32/mp` package, modeling Cortex-A application cores,
Cortex-M firmware, multi-stage boot chains, device tree bindings, TrustZone security domains,
and shared resources as distinct execution units and separate programs per TOPO-004 and STM-015
without weakening MCU assumptions. The 53 curated MCU parts remain untouched and isolated from
MPU workflows. Flagship targets include:
- `STM32MP157`: dual Cortex-A7 32-bit cores plus Cortex-M4 32-bit coprocessor;
- `STM32MP257`: dual 64-bit Cortex-A35 cores plus Cortex-M33 and low-power SmartRun Cortex-M0+;
- `STM32MP135`: single Cortex-A7 32-bit application core without microcontroller coprocessor.

All 53 curated MCU parts remain `PLANNED`; T039-T048 artifacts, every pinned snapshot,
every device-data and signature pack, and every support state are unchanged. No Ghidra
mutation adapter is added (`NO_ADAPTER_PURE_PLAN_ONLY`).

The repository builds 394 unit tests (16 new T049 tests) and 104 real-Ghidra integration
tests, and the STM32 Python suite reports 131 tests (`OK (skipped=4)`, the four pre-existing
optional pinned-source checks) plus 4 ESP Python tests. The reproducible completion gate
passes with two clean, uncached 22-action builds and a byte-identical extension ZIP, SHA-256
`13f6fde3544aefca18fef29788074d6718fba62ef68d05e08af1a22c882822b2` (4,512,940 bytes).

## Scope and invariants

- The pure/adapter boundary holds. All T049 classes live under `targets.stm32.mp`; they import
  `core` and `targets` model classes only and never import a Ghidra API. No Ghidra mutation
  exists in this task (`NO_ADAPTER_PURE_PLAN_ONLY`).
- STM-015 separation: STM32MP devices are a distinct heterogeneous microprocessor class;
  they are never loaded as ordinary Cortex-M-only firmware. `Stm32MpProviderRegistry` isolates
  MPU targets, and MCU queries reject MPU parts while MPU queries reject MCU parts.
- TOPO-004 execution topology: heterogeneous execution units (Cortex-A, Cortex-M, BootROM) are
  represented as distinct `ProcessorNode` records with their specific ISA, Ghidra language ID,
  reset vectors, and roles. The topology declares `ProgramStrategy.SEPARATE_PROGRAMS`.
- Boot chain modeling: `Stm32MpBootChainPlan` models each stage across BootROM, TF-A BL2 FSBL,
  OP-TEE BL32 Secure OS, U-Boot BL33 SSBL, Linux OS, and remoteproc coprocessor firmware.
  Selectable boot architectures (`A35_TRUSTED_DOMAIN` vs `M33_TRUSTED_DOMAIN` on MP257) are
  modeled per TOPO-006.
- Device tree bindings: `Stm32MpDeviceTreePlan` and pure `Stm32MpDeviceTreeParser` extract
  remoteproc nodes, mailbox controllers (`IPCC`), hardware semaphores (`HSEM`), and reserved
  memory blocks under shared `ParserLimits` and cooperative `CancellationToken`.
- TrustZone security domains: `Stm32MpSecurityPlan` models hardware security firewalls
  (`ETZPC` on MP1, `RIF` on MP2) and non-volatile OTP security (`BSEC` / `BSEC3`).
- Shared resources: `Stm32MpSharedResourcesPlan` models shared SRAM apertures (`SYSRAM`,
  `MCURAM`, `RETRAM`), hardware mailboxes, and hardware semaphores.
- Multi-program workspace: `Stm32MpWorkspacePlan` assigns distinct Ghidra program slots per
  domain and architecture with explicit cross-program references (`BOOT_HANDOFF`,
  `SHARED_MAILBOX`, `SHARED_SEMAPHORE`, `SHARED_MEMORY`).
- License and provenance audit: redistributable inputs are audited and pinned:
  - Linux kernel device tree sources (`arch/arm/boot/dts/st/stm32mp157c.dtsi`,
    `arch/arm64/boot/dts/st/stm32mp257.dtsi`, `stm32mp251.dtsi`): `GPL-2.0+ OR BSD-3-Clause` / `GPL-2.0-or-later OR BSD-3-Clause`.
  - ARM TF-A stm32mp1/stm32mp2 platform ports: `BSD-3-Clause`.
  - ST CMSIS device headers (`cmsis-device-mp2 dbda522`, `cmsis_device_mp13 fbbe3df`): `Apache-2.0`.
  - ST open pin data: `BSD-3-Clause`.
  - OpenOCD scripts (`stm32mp15x.cfg`, `stm32mp25x.cfg`, `stm32mp13x.cfg`): `GPL-2.0-or-later`.
- Pinned minimal fixture: `src/test/resources/fixtures/stm32mp/stm32mp157c-minimal.dts`
  with matching manifest and provenance validation pass.
- STM-019: all 53 curated MCU parts remain `PLANNED`. All STM32MP targets remain `PLANNED`.

## Implemented model

### `targets/stm32/mp/Stm32MpTargetProvider`

Interface declaring exact part, line, family, confidence, evidence, matching, support decision,
execution topology, boot chain plan, device tree plan, security plan, shared resources plan,
and workspace plan.

### Target Providers

- `Stm32Mp157TargetProvider`: covers STM32MP157C (dual Cortex-A7 32-bit @ 800MHz + Cortex-M4 32-bit @ 209MHz),
  SYSRAM (256 KiB at 0x2FFC0000), MCURAM (384 KiB at 0x10000000, aliased at 0x30000000), RETRAM (64 KiB),
  IPCC mailbox at 0x5C001000, HSEM spinlocks at 0x5C000000, ETZPC firewall at 0x5C007000, BSEC OTP at 0x5C005000.
- `Stm32Mp257TargetProvider`: covers STM32MP257F (dual 64-bit Cortex-A35 @ 1.5GHz + Cortex-M33 @ 400MHz +
  Cortex-M0+ SmartRun @ 200MHz), SYSRAM (256 KiB at 0x0E000000), SRAM1/2/3/4, IPCC1/2 mailboxes, HSEM semaphores,
  RIF firewall at 0x42080000, BSEC3 OTP at 0x44000000. Supports selectable boot flavors (`A35_TRUSTED_DOMAIN`
  and `M33_TRUSTED_DOMAIN`).
- `Stm32Mp135TargetProvider`: covers STM32MP135F (single Cortex-A7 @ 1.0GHz without microcontroller coprocessor),
  SYSRAM (128 KiB at 0x2FFE0000), ETZPC at 0x5C007000, BSEC at 0x5C005000.

### `targets/stm32/mp/Stm32MpDeviceTreeParser`

Pure parser extracting remoteproc nodes, mailbox controllers, hardware semaphores, and reserved-memory
carving from DTS excerpts under shared `ParserLimits` and cooperative `CancellationToken`.

### `targets/stm32/mp/Stm32MpProviderRegistry`

Registry isolating MP target resolution from ordinary MCU catalog resolution (STM-015).
