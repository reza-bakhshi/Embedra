## Correctness review checkpoint — 2026-10-01

An independent review found four real correctness gaps after the first pass.
All four were corrected, and the readiness audit was strengthened so each is
now fail-closed:

1. **WB15 was missing its second core.** The plan cited evidence naming a
   Cortex-M0+ (CPU2) but declared `physicalCoreCount: 1` with profile
   `WB_SINGLE_CORE`. `STM32WB15CCU6` now uses profile `WB_DUAL_CORE` with a
   `secondaryCore` of Cortex-M0+, IPCC (`0x58000C00`) and HSEM (`0x58001400`)
   ranges, and a CPU2 release-from-reset relationship (RM0473 Rev 9 sections
   2.1.4/2.4 and Table 1). The planner emits both CPU cores and their links.
2. **H735's configurable RAM was an unconditional mapping.** RM0468 Rev 3
   section 2.4/Table 8 shows the 192-KiB bank is repartitioned between ITCM and
   AXI by `TCM_AXI_SHARED[1:0]`. The plan now marks that region
   `"configuration": "ITCM_AXI_SHARED"` and records a
   `configurationDependentRegions` entry with the four documented allocations.
   The planner places it only when an explicit allocation is supplied
   (`plan(part, bootMode, Map.of("ITCM_AXI_SHARED", id))`); otherwise it is
   reported in `unresolvedConfigurationRegions` and the resolved map contains
   only the fixed 372 KiB.
3. **WB55/WB15 access permissions overclaimed sharing.** The planner granted
   both cores read/write to every RAM bank. `SharedMemoryRegion` access is now
   data-driven via a per-region `sharedAccess` map: SRAM1 stays read/write for
   CPU1 and CPU2, while SRAM2A/SRAM2B are CPU2-only because a
   user-option-selected section is CPU2-secure and inaccessible to CPU1
   (RM0434 Rev 12 section 3.4.1; DS11929 Rev 16 section 3.3.4). No configuration
   input is required because the model now underclaims rather than inventing
   CPU1 write access.
4. **The readiness audit had validation holes.** `plan_gaps` now additionally
   rejects: a dual-core profile with `physicalCoreCount != 2` (and the reverse),
   a missing or malformed IPCC/HSEM range on a dual-core profile, an
   out-of-enum `flash`/`system`/`option` availability value, a `FLASH` region
   present while `flashAvailability` is `UNAVAILABLE`, an invalid
   `configuration` marker or `sharedAccess` map, and a
   `configurationDependentRegions` entry whose declared size or allocations do
   not match the region. Regression tests in
   `scripts/tests/test_audit_stm32_memory_readiness.py` and
   `Stm32MemoryPlannerTest` exercise each hole.

## Intra-allocation overlap checkpoint — 2026-10-02

## Hardening addendum — 2026-10-02
