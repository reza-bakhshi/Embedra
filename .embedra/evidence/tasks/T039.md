# T039 Evidence — STM32 memory-region and topology planning

## Status

`IN_PROGRESS` on 2026-09-30. The pinned curated catalog has no verified
memory-bank rows for any of its 53 exact parts. Eleven records have unpaired
flash sizes; all 53 have processor identities. A strict completeness gate
therefore fails, and no exact STM32 device memory map is promoted.

## Completed checkpoint

- Added `scripts/audit-stm32-memory-readiness.py`. It checks the committed
  curated-catalog SHA-256 and schema, reports per-part missing mandatory
  properties, and exits nonzero with `--require-complete` while any record is
  incomplete. It does not substitute family defaults or infer bank addresses.
- Added three tests for the 53-record baseline, digest failure, and unknown
  flash/bank preservation. `verifySTM32CatalogGenerator` passes 61 Python
  tests. The completeness command exits 1 by design: 0 ready parts, 53 missing
  bank maps, 11 unpaired flash sizes, 0 missing processor lists.
- Audited 19 relevant Open-CMSIS-Pack STM32 DFP descriptors. Their repository
  HEAD commits and raw PDSC SHA-256 values are pinned in
  `T039-dfp-source-audit.json`; no vendor PDSC rows are packaged. License-set
  metadata lists Apache-2.0 for 11 and Apache-2.0 plus BSD-3-Clause for 8.
  Direct exact-name patterns cover 43 selected parts; seven more have shorter
  prefix candidates that require explicit suffix/package reconciliation. The
  three F103 parts have no match in this source set and need separate
  ST-authored memory evidence.
- Initial memory-node inspection confirms that PDSC inheritance, child
  overrides, security aliases, and alternate flash views matter. For example,
  the F756 descriptor exposes `Flash` and `ITCM_Flash` windows of equal size;
  these cannot be summed as two physical flash banks. WB0 SRAM child entries
  can override inherited names. No candidate map is accepted until these
  relationships and catalog capacities are reconciled per exact part.
- Added `scripts/generate-stm32-memory-candidates.py` and six focused tests.
  The offline transform checks all 19 descriptor hashes against the pinned
  source audit, rejects DTD/entities and oversized XML, applies memory-node
  inheritance and child override by name, preserves every attribute and
  declaration path, and distinguishes direct patterns from shorter prefix
  candidates. It does not classify physical capacity or silently collapse
  aliases and competing device matches. Re-running it produces the same
  `T039-memory-candidates.json` bytes.
- The generated evidence has 53 selected records, with descriptor candidates
  for 50. It contains 51 candidate paths and 306 memory declarations, of
  which 102 carry explicit alias attributes. The three F103 records have
  `NO_DFP_MATCH`. WL33CCV6TR has two competing prefix paths and remains
  ambiguous. All candidates are `UNREVIEWED`; none is a runtime memory map.
- Direct comparison exposes reconciliation work: G491RET6 has catalog RAM
  128 KiB versus a 112 KiB DFP SRAM node; H735IGK6 has catalog 564 KiB
  versus 496 KiB across the named DFP RAM nodes; H750XBH6 has catalog
  864 KiB versus 992 KiB across named DFP RAM nodes. WB05 SRAM windows
  overlap, while F756 has two 1 MiB flash views. The DFP declarations do
  not themselves include all system/OTP/option areas. These are review
  findings, not corrected catalog values.
- `verifySTM32CatalogGenerator` passes 67 Python tests at this checkpoint.
