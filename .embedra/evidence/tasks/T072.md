## 1. Verified Coverage Areas & Behavioral Guarantees

### A. Program-Transaction Rollback Semantics (`GhidraProgramTransaction`)
- **AutoCloseable Auto-Rollback**: Any transaction closed without an explicit `commit()` call closes as a rollback via `program.endTransaction(id, false)`. Verified with initialized memory blocks where block disappears upon close.
- **Commit Request Enforcement**: Explicit `commit()` sets the commit flag; transaction ends with `program.endTransaction(id, true)`.
- **Closed State Invariants**: Attempting to call `commit()` after close throws `IllegalStateException`.
- **Idempotent Double-Close**: Repeated `close()` invocations on an already closed transaction are safe no-ops and never issue duplicate `endTransaction` calls.
- **Input Preconditions**: Null `Program` instances throw `NullPointerException`; null or blank transaction descriptions throw `IllegalArgumentException`.

### B. Subsystem Import and Mapping Rollback on Conflict / Failure
- **ESP32-S3 Application Image Mapper** (`EspApplicationImageMapper`):
  - When mapping into a program with an existing conflicting memory block, throws `EspMappingException` with code `ESP_MAPPING_CONFLICT`.
  - Transaction rolls back: existing user memory block remains unmodified with original bytes and permissions preserved; zero new memory blocks, labels, or entry points are committed.
- **ESP8266 Legacy Image Mapper** (`Esp8266LegacyImageMapper`):
  - Conflicting memory block throws `EspMappingException` with code `ESP_MAPPING_CONFLICT`.
  - Transaction rolls back: existing user memory block remains unmodified; zero new blocks or options committed.
- **Raspberry Pi UF2 / Firmware Mapper** (`RpFirmwareMapper`):
  - Conflicting memory block throws `RpMappingException` with code `RP_MAPPING_CONFLICT`.
  - Transaction rolls back: existing user block remains unmodified; zero bookmarks, entry points, or options committed.
- **STM32 Raw Binary Importer** (`Stm32RawBinImporter`):
  - Contradictory recorded exact part in program options throws `IOException`.
  - Transaction rolls back: program options retain original part; zero memory blocks committed.
- **STM32 Vector Table Applicator** (`Stm32VectorApplicator`):
  - Memory byte or instruction collision with vector candidate throws `IOException`.
  - Transaction rolls back: options under `Embedra STM32 Vector Table` remain unset; zero data types created.
- **STM32 External Memory Applicator** (`Stm32ExternalMemoryApplicator`):
  - Length mismatch between ByteProvider and load plan throws `Stm32MappingException`.
  - Transaction rolls back: zero external memory blocks committed.

### C. Cooperative Cancellation Across All Components
- **Preemptive Cancellation**:
  - `EspApplicationImportService`: passing a cancelled `TaskMonitor` immediately throws `DiagnosticException` with code `CANCELLED`; zero blocks, entry points, or options are touched.
- **Mid-Operation Cancellation during Segment Iteration**:
  - `EspApplicationImageMapper`: cancellation during segment creation loop throws `CancelledException`; uncommitted transaction rolls back, leaving 0 blocks in program memory.
  - `Esp8266LegacyImageMapper`: cancellation during segment creation loop throws `CancelledException`; uncommitted transaction rolls back, leaving 0 blocks.
  - `RpFirmwareMapper`: cancellation during segment creation loop throws `CancelledException`; uncommitted transaction rolls back, leaving 0 blocks and 0 bookmarks.
- **Cooperative Cancellation Across Ghidra Applicators**:
  - `GhidraCryptoApplicator`: cancellation mid-findings skips `tx.commit()`; transaction rolls back, leaving 0 bookmarks and options untouched.
  - `GhidraCtfApplicator`: cancellation mid-entities skips `tx.commit()`; transaction rolls back, leaving 0 bookmarks and options untouched.
  - `GhidraYaraApplicator`: cancellation mid-matches throws `CancelledException`; transaction rolls back, leaving 0 bookmarks and options untouched.
  - `GhidraStringApplicator`: cancellation mid-strings skips `tx.commit()`; transaction rolls back, leaving 0 bookmarks and options untouched.
  - `GhidraLoggingApplicator`: cancellation mid-callsites skips `tx.commit()`; transaction rolls back, leaving 0 bookmarks and options untouched.
  - `GhidraSecurityLeadApplicator`: updated to check cancellation cooperatively via `monitor.checkCancelled()`; cancellation skips `tx.commit()`, rolling back all annotations and options.
  - `GhidraPluginApplicator`: updated to check cancellation cooperatively via `monitor.checkCancelled()`; cancellation skips `tx.commit()`, rolling back all plugin bookmarks and options.
  - `EmbedraFunctionNormalizer`: cancellation mid-functions throws `CancelledException`; transaction rolls back, leaving function calling conventions unmodified.
  - `GhidraWorkspaceDiffExtractor`: cancellation token throws `DiagnosticException` with code `CANCELLED`; read-only analysis terminates cleanly without partial state.

### D. Partial-Workspace Cleanup in Multi-Program Imports
- **Multi-Program Full-Flash Loader (`EspApplicationImageLoader.loadWorkspace`)**:
  - Multi-program layout with factory application and bootloader (`default-factory.bin`).
  - **Cancellation Case**: When cancellation occurs during the loading of subsequent executables in the workspace, `loadWorkspace` catches `CancelledException`, executes `loadedPrograms.forEach(Loaded::close)` to release previously opened programs, and releases the in-flight program in `finally`. Zero open programs remain attached to the consumer.
  - **Failure Case**: When an error occurs during parsing or mapping of a subsequent executable, `loadWorkspace` catches the failure, closes all previously created programs in `loadedPrograms`, and propagates the exception. Zero orphaned programs remain leaked in the Ghidra workspace.
