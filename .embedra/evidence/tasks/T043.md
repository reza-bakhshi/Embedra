# T043 Evidence — STM32 HAL/LL/CMSIS/FreeRTOS signature-pack generation and matching

## Status

`COMPLETE` on 2026-10-02. T043 adds a pure, evidence-gated STM32 library
signature-pack pipeline: a deterministic generator that compiles a pinned
redistributable STM32Cube F1 package with a pinned `arm-none-eabi-gcc` and
records relocation-masked function byte signatures, an integrity-first pack
loader, and a bounded matcher that applies a signature only when the exact
family, compiler, and optimization are recorded. Every one of the 53 curated
exact parts remains `PLANNED`; T039 memory plans, T040 device-data packs, T041
vector behavior, and T042 board profiles are not modified, and T044 is not
started.

The repository builds 291 unit tests, 93 real-Ghidra integration tests, 123
STM32 Python tests (4 documented optional-source skips), and 4 ESP Python tests.
The reproducible gate passes with two clean, uncached 22-action builds and a
byte-identical 4,186,407-byte extension ZIP, SHA-256
`867e619d081c7dd922ed1b0f6d59ac50db2d2aa6305cb6fb228ff526f698aa14`.

## Scope and invariants

- The pure/adapter boundary holds: `Stm32LibrarySignature`, `Stm32SignaturePack`,
  `Stm32SignaturePackLoader`, `Stm32SignatureContext`, `Stm32FunctionBytes`,
  `Stm32SignatureMatcher`, `Stm32SignatureMatch`, `Stm32SignatureNonMatch`,
  `Stm32SignatureMatchReport`, and `Stm32SignaturePackSelection` live under
  `analyzers`; no Ghidra API is imported.
- STM-012: a signature is applied only when the caller records the exact device
  family, compiler identity, and optimization level. Missing evidence returns an
  explicit `EVIDENCE_MISSING` non-match and scans nothing; an evidence key with
  no indexed signature returns `INDEX_UNAVAILABLE`; a scanned but unmatched
  function returns `NO_MATCH`. No absent-scan or absent-index result is ever
  reported as a match.
- A signature match is a function-identification fact with `DERIVED` (masked) or
  `VERIFIED` (fully specified) confidence and explicit pack provenance. It does
  not verify a device, and no support state changes.
- The generator input is pinned and redistributable: `STM32Cube_FW_F1_V1.8.7`
  (archive SHA-256 `1b5f99f86982efe5e4931063de4a0f0af80e38a05d4835b0b8f82aefad634b29`),
  only BSD-3-Clause (HAL/LL), Apache-2.0 (CMSIS Device), and MIT (FreeRTOS)
  components. No source, header, object, or toolchain runtime is bundled; only
  derived names, source-relative provenance, and masked byte patterns ship.
- Malformed, truncated, oversized, duplicate, unknown-family, and invalid-hex
  entries fail closed with stable `PACK_*` diagnostics. All scanning is bounded
  by the shared `ParserLimits` and cooperative cancellation.

## Implemented model

### Deterministic generator

`scripts/generate-stm32-signatures.py` compiles every reviewed source file with
`-ffunction-sections` at the recorded optimizations (`-Os`, `-O2`), parses the
little-endian ELF object directly, extracts each `.text.<function>` section as a
pattern, and masks every byte touched by an ELF relocation (calls and absolute
pointers). Functions shorter than 8 bytes or with fewer than 8 significant bytes
are excluded and counted. The run is deterministic: regeneration reproduces the
committed `pack.json`, `signatures.json`, and source audit byte-for-byte. The
committed slice has 1,543 signatures across five components (STM32F1 HAL 1,111;
FreeRTOS kernel 225; LL 179; FreeRTOS GCC Cortex-M3 port 24; CMSIS Device 4),
with zero compile skips and 420 low-specificity functions excluded.

### Pack model and loader

`Stm32LibrarySignature` validates non-blank identity, a 64-hex source digest, a
pattern/mask length of at least 8 equal bytes, mask bytes limited to `00`/`ff`,
and at least one significant byte. `Stm32SignaturePack` requires non-empty,
unique signature ids whose family is declared by the manifest.
`Stm32SignaturePackLoader` verifies the exact pack id, the pinned license and
source revision, `ALLOWED` redistribution, the aggregate `PackIntegrity` content
digest, and a closed content schema before exposing signatures.
`Stm32SignaturePackSelection` wires loading through the shared offline
`LocalPackRepository` selection path (integrity-first, highest-compatible, no
network).

### Evidence-gated matcher

`Stm32SignatureMatcher.match` enforces `ParserLimits` and cancellation, then
indexes the pack by `(family, compiler, optimization)`. With complete evidence
it prefix-matches each bounded candidate function and emits sorted matches plus
explicit, bounded non-matches (at most 128 function details and one overflow
summary). Fully specified signatures yield `VERIFIED`/`EXACT_SIGNATURE_MATCH`;
masked signatures yield `DERIVED`/`DERIVED_RULE`.

### Pinned source audit

`.embedra/evidence/tasks/T043-signature-source-audit.json` (SHA-256
`9bcffd9259e43c9bc256b67bba5f7c7bb8b5dd54d685efb7ec9eee598c05fddf`) records the
package archive digest, compiler identity, defines, flags, optimizations, the
two pinned config headers, the per-file SHA-256 of every compiled source, and the
generated pack digest. The pack manifest pins its own aggregate content digest
`ebb0e4e72b435d13b23f42945fc5e62056d82b390921e5ad5a007bc2b227a191`
(`pack.json` SHA-256 `7f80d9f9bfb553da5545ceb5467f45e506b525a02851828043a034361b840100`;
`signatures.json` SHA-256 `c21f553e30a5d02b30aaafa4bd0584ac3deaf304b23d895d7d692cedbbd8dc70`).

### Ghidra adapter boundary

Applying matched names or comments to a Ghidra program is deliberately out of
scope for T043, matching the task's optional wording. The pack is loaded and
matched purely and integrated through the shared pack-selection contract; no
Ghidra mutation or new integration test is added.

## Preserved boundaries and limitations

- T039 memory plans (`00def2817b…`), the T040 applicability artifact
  (`be795ab0…`) and device-data packs, T041 vector behavior, and the T042 board
  profiles are unchanged.
- All 53 curated parts remain `PLANNED`; T043 promotes no support state. A
  family-level signature match is explicitly scoped to `STM32F1` and never
  resolves an exact part.
- Only the STM32F1 slice ships. Other STM32 families, HAL versions, compilers,
  optimization levels, and RTOS/library versions are not claimed; a missing key
  stays `EVIDENCE_MISSING` or `INDEX_UNAVAILABLE`.
- Signatures are valid only for the pinned compiler and optimizations. A build
  with a different compiler or optimization fails closed rather than matching
  approximately.
- The pack contains derived masked byte patterns; no vendor source, header,
  object, or toolchain runtime is redistributed.
- No Ghidra program mutation is performed, so no functional name is applied to a
  real program by T043.
