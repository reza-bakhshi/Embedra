# T066 Evidence — Positive/Negative Crypto Corpora, Per-Detector Metrics, Precision, Recall, and Unsupported Cases

## Status

`COMPLETE` on 2026-10-10. T066 implements positive and adversarial negative cryptographic corpora across ESP, STM32, RP2040, and RP2350 family ISAs/toolchains, measures per-detector precision, recall, false-positive rate, confidence calibration, and explicitly tracks unsupported cases (AN-003, AN-010, AN-012, AN-013, AN-014, AN-015):

- Cryptographic Corpus Models & Dataset (`io.github.rezabakhshi.embedra.analyzers.crypto.corpus`):
  - `CryptoCorpusClassification`: `POSITIVE`, `NEGATIVE_ADVERSARIAL`, `UNSUPPORTED_VARIANT`.
  - `CryptoDetectorType`: 7 evaluated detector subsystems (`CONSTANT_TABLE`, `LIBRARY_SIGNATURE`, `HARDWARE_PERIPHERAL`, `VENDOR_ROM`, `KEY_MATERIAL`, `ENTROPY_ANALYSIS`, `FUSED_PIPELINE`).
  - `UnsupportedReason`: Taxonomy of unsupported cryptographic variants (`VECTORIZED_SIMD_WITHOUT_STANDARD_PROLOGUE`, `PROPRIETARY_SECURE_ENCLAVE`, `BITBANGED_SOFTWARE_CRYPTO`, `CUSTOM_INLINED_WITHOUT_CONSTANTS`).
  - `UnsupportedCase`: Explicit record of unmodeled variants with rationale and roadmap mitigation to guarantee "not found" is never confused with "not present" (AN-012).
  - `CryptoCorpusSample`: Self-contained immutable test fixture containing target platform, ISA, toolchain metadata, binary payload, base address, symbol leads, hardware accesses, call sites, cross-program references, expected algorithms, and expected detectors.
  - `CryptoCorpus`: Deterministic 31-sample benchmark corpus:
    - 12 Positive Samples:
      - ESP32 (Xtensa LX6): AES-128 via mbedTLS and hardware MMIO.
      - ESP32-S3 (Xtensa LX7): AES & SHA accelerator with ESP-IDF wrappers and vendor ROM call.
      - ESP32-C3 (RISC-V 32): SHA engine and ESP-IDF AES wrapper.
      - ESP32-C6 (RISC-V 32): ECC accelerator & HMAC key material.
      - STM32F4 (ARM Thumb): CRYP AES engine with HAL wrappers.
      - STM32F7 (ARM Thumb): Hardware HASH SHA-256 accelerator and candidate key.
      - STM32H7 (ARM Thumb): CRYP engine and hardware TRNG.
      - STM32L4 (ARM Thumb): AES engine and TinyCrypt wrapper.
      - STM32WB (ARM Thumb): Dual-core IPCC key mailbox, PKA trigger, and mbedTLS signature.
      - RP2040 (ARM Thumb Cortex-M0+): Boot ROM lookup ('RE'), ATECC608A I2C, and ChaCha20 signature/constants.
      - RP2350 (ARM Thumb Cortex-M33): Hardware SHA-256 accelerator and Pico SDK wrappers.
      - RP2350 (Hazard3 RISC-V 32): Hardware TRNG read and 128-bit candidate key.
    - 15 Adversarial Negative Samples:
      - Non-crypto lookup tables: DSP trigonometric sine table, CRC-32 IEEE, CRC-16 CCITT, RFC 4648 Base64 alphabet, hexadecimal ASCII translation table, Huffman frequency distribution, POSIX ctype character classification matrix, Deflate fixed distance table, LZ4 compressed frame header & tokens.
      - Non-crypto high-entropy data: Ogg Opus compressed audio, JPEG JFIF image stream, procedural Perlin noise permutation table.
      - Non-crypto code idioms: ARM Thumb compiler jump table, RISC-V branch jump table, Xtensa literal pool with non-crypto MMIO addresses.
    - 4 Explicit Unsupported Cases:
      - `unsupported-esp32-custom-vectorized-chacha20`: Vectorized Xtensa ChaCha20 quarter-round without standard prologue.
      - `unsupported-stm32-proprietary-secure-enclave`: Proprietary OP-TEE TrustZone SMC enclave interface.
      - `unsupported-rp2040-bitbanged-software-crypto-pio`: Bit-banged AES running in RP2040 PIO microengine.
      - `unsupported-inlined-aes-without-sbox`: Bitsliced algebraic AES without S-box tables.
- Pure Evaluation & Metrics Engine:
  - `DetectorEvaluation`: Computes TP, FP, TN, FN, Precision, Recall, False-Positive Rate, F1 score, and confidence distribution per detector.
  - `AlgorithmEvaluation`: Computes TP, FP, FN, Precision, Recall, F1 score per cryptographic algorithm.
  - `ConfidenceCalibration`: Computes total counts, correct detections, false leads, and accuracy across four confidence tiers (`CONFIRMED`, `LIKELY`, `PLAUSIBLE`, `LEAD`).
  - `CryptoCorpusBenchmark`: Pure evaluation engine executing detectors under `ParserLimits` and `CancellationToken`.
  - Strict AN-003 Enforcement: Validates that non-crypto adversarial negative samples never receive `isEncryption() == true`.
