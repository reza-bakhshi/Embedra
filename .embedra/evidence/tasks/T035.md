# T035 Evidence — STM32 DfuSe container parsing

## Status

`COMPLETE` on 2026-09-30. T036 raw BIN import and T038 exact-part selection
remain unimplemented; no STM32 catalog part is promoted from `PLANNED`.

## Supported format and implementation

The pure `Stm32DfuParser` supports addressed DfuSe version 1 containers. It
checks the `DfuSe` prefix, version and complete-file size, target count,
`Target` headers, alternate settings, target-name flag, exact target and
element lengths, 32-bit element addresses, no overlap within a target, and
the 16-byte `UFD` suffix with DFU revision `0x011a` and complemented CRC-32.
It enforces input, object, extracted-byte, cancellation, and elapsed-time
limits. The immutable `Stm32DfuImage` retains source ranges for payloads;
the parser does not copy firmware bytes, select a device, or map Ghidra memory.

The format contract was checked against ST's UM0391 DfuSe File Format
Specification and the independently maintained dfu-util `dfuse-pack.py`
implementation, which confirms little-endian multibyte fields and the
complemented CRC used by real DfuSe files:

- https://community.st.com/ysqtg83639/attachments/ysqtg83639/interface-connectivity-ics-forum/3972/1/UM0391.pdf
- https://sources.debian.org/src/dfu-util/0.11-1/dfuse-pack.py/

This is a strict supported subset. It rejects zero-element targets, repeated
alternate settings, overlapping elements, and older files whose prefix size
excludes the suffix. A generic DFU suffix on an otherwise raw BIN is outside
this container parser.
