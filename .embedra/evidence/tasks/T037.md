# T037 Evidence — Cortex-M vector discovery and confirmation

## Status

`COMPLETE` on 2026-09-30 for the explicit confirmation API. Exact-part search,
device maps, GUI selection workflow, interrupt labels, and handler functions
remain T038-T041. All 53 exact STM32 catalog records remain `PLANNED` for
device support; this task does not infer a raw BIN base or part number.

## Implementation

- Pure `Stm32VectorDiscovery` scans bounded 4-byte offsets with a proposed
  32-bit image base and caller-supplied known RAM intervals. Candidates need
  an aligned stack top within RAM, an in-image Thumb reset handler, at least
  three other in-image handlers in the first 16 words, and at most two invalid
  nonzero entries. Scores also reflect table alignment and handler density.
  Candidate records retain source offset, target address, first 16 words,
  score, and input SHA-256. Discovery is heuristic and does not select a part.
- `confirm` requires the caller to select a reported table address. The
  Ghidra applicator accepts only that confirmation, verifies every mapped
  vector word, rejects conflicting instructions/data or prior confirmed
  address, and creates 16 primitive dwords transactionally. Reapply is
  idempotent. It records confirmation and discovery-input provenance.
- No automatic base inference or GUI prompt is wired yet. A GUI or headless
  caller must supply the selected candidate explicitly; T038 owns the
  exact-part selection workflow, and T041 owns vector names/functions.
