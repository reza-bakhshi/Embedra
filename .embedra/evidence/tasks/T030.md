## Providers and fixtures

- Added maintained esptool 5.4.0 image chip IDs and independent providers for
  ESP32-S31, P4, C2, C5, C6, C61, E22, H2, H21, and H4.
- Every provider selects Ghidra `RISCV:LE:32:default`, compiler specification
  `gcc`, and two-byte instruction alignment. Memory ranges use pinned ESP-IDF
  v6.0 `soc.h` evidence where present; S31 and E22 use the maintained esptool
  memory maps because that ESP-IDF revision has no target directory for them.
- Processor topology records each cataloged application processor and the P4,
  C5, and C6 low-power RISC-V processor. The common resolver now covers all 14
  cataloged ESP32 series without target-specific architecture assumptions.
- Added ten independently linked and esptool-converted 65,600-byte fixtures,
  target-specific linker addresses and flash frequencies, manifests, esptool
  image-info oracles, and ELF program-header oracles. Two generations produced
  identical SHA-256 sets and fixture provenance validation passed.

## Enrichment packs

Pinned ESP-IDF revision
`662a3be354759d9487bf4b1a629fadb766cb1800` generated the available ROM and
peripheral-header packs. Pinned Espressif SVD revision

## Boundaries

The image header does not identify exact flash/PSRAM/package variants, so the
catalog results are candidates only. No LP/ULP firmware analysis, target-specific
full-flash workspace, module/board support, hardware behavior, or hardware
verification is claimed. S31/E22 enrichment and the absent SVD targets remain
explicitly unavailable rather than synthesized.
