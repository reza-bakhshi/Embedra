# T030 Evidence — Remaining ESP Providers

## Status

`IN_PROGRESS` on 2026-09-25. T031 has not started.

## Completed foundation slice

- Added maintained esptool 5.4.0 image chip IDs for ESP32-S31, P4, C2, C5,
  C6, C61, E22, H2, H21, and H4.
- Added an independent provider class for every remaining cataloged series.
- Each provider selects Ghidra `RISCV:LE:32:default` with compiler
  specification `gcc` and two-byte instruction alignment.
- Memory ranges come from pinned ESP-IDF v6.0 `soc.h` files where present.
  ESP32-S31 and ESP32-E22 use their esptool 5.4.0 `MEMORY_MAP` because the
  pinned ESP-IDF revision has no source directory for those two targets.
- Processor topology records the cataloged application-core counts. P4, C5,
  and C6 additionally record their cataloged low-power RISC-V processor.
- The target resolver now recognizes all fourteen cataloged ESP32 series.

Implementation commit: `365d7af5c3245bbe2af5d347601b129cbda69df8`.

Fixture commit: `e3c5ee03cd76fc9bd7a200f83aa3dce9016a76f5`. It adds ten
independently linked and esptool-converted 65,600-byte images, target-specific
linker addresses and flash frequencies, manifests, image-info oracles, and ELF
program-header oracles. Two consecutive generations produced identical SHA-256
sets, and `validate-fixture-provenance.sh` passed.
