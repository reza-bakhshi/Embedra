# T086 Evidence — Real-Ghidra GUI and Headless Multi-Program Import for All 14 ESP Series

## Status

`COMPLETE` on 2026-10-13. T086 wires every proven ESP flash layout plan into real-Ghidra GUI and headless
multi-program import via `EspApplicationImageLoader`. It independently verifies bootloader and application
byte, address, language, and entry mappings, opaque artifact handling, OTA partition planning, cancellation
rollback, repeat-import idempotence, and canonical GUI/headless workflow equality across all 14 series
(`ESP32`, `ESP32-S2`, `ESP32-S3`, `ESP32-C3`, `ESP32-C2`, `ESP32-C5`, `ESP32-C6`, `ESP32-C61`,
`ESP32-H2`, `ESP32-H21`, `ESP32-H4`, `ESP32-P4`, `ESP32-S31`, `ESP32-E22`).

## 1. Deliverables

1. **Multi-Program Import Integration**:
   - `EspApplicationImageLoader`:
     - Discovers and plans full-flash captures across all 14 cataloged series via `EspFullFlashWorkspacePlanner`.
     - Detects target architecture from candidate headers (offset `0x0000` or `0x1000` for ESP32) and
       yields target-matched `LoadSpec`:
       - `Xtensa:LE:32:default` (`default`) for ESP32 and ESP32-S2.
       - `Xtensa:LE:32:esp32s3` (`default`) for ESP32-S3.
       - `RISCV:LE:32:default` (`gcc`) for all 11 RISC-V series (`C3`, `C2`, `C5`, `C6`, `C61`,
         `H2`, `H21`, `H4`, `P4`, `S31`, `E22`).
     - Extracts and maps each executable slot into separate Ghidra `Program` instances:
       - Second-stage bootloader at `0x0000` (`0x1000` on ESP32).
       - Factory application at `0x10000`.
       - OTA application slots (`ota_0` and `ota_1`).
     - Preserves immutable provenance per program in `Embedra Full Flash Provenance` (`Partition Table Offset`,
       `Executable Flash Length`, `Source SHA-256`).
     - Preserves opaque data partitions: encrypted assets, NVS, PHY, and SPIFFS are retained as labeled
       workspace assets and never sent to the CPU disassembler.
     - Target-matched enrichment packs: applies SVD and ROM symbol packs for ESP32-S3 and targets with
       bundled packs; marks other targets cleanly with `ESP_<TARGET>_ENRICHMENT_UNAVAILABLE` or `DISABLED`.

2. **Automated Verification**:
   - `EspFullFlashMultiProgramImportIntegrationTest` (`src/integrationTest/java/io/github/rezabakhshi/embedra/ghidra/esp/EspFullFlashMultiProgramImportIntegrationTest.java`):

       - Verifies fail-closed rejection of `invalid-partition-md5.bin` and `malformed-wrong-chip.bin` across

     - `testCooperativeCancellationRollsBackMultiProgramImport`:

         intermediate program handles.
     - `testRepeatImportIdempotence`:
       - Proves repeat imports produce identical program databases and workspace snapshots.
