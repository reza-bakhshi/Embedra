## Test-first and implementation evidence

The initial test failed compilation with 23 absent security-contract symbols.
The implementation now reports valid/invalid/absent appended image hashes,
structurally valid RSA V2 signature blocks, encrypted partition labels, and
NVS-key/encrypted-NVS indicators. CRC-valid signature structure is `DERIVED`;
cryptographic verification stays `UNKNOWN`. Secure Boot and flash-encryption
eFuse states stay `UNAVAILABLE`, so `secureBootEnabled()` is never inferred from
an offline image. Inputs/results are immutable, bounded, cancellable, sorted,
and contain no key bytes.

The clean run passed 125 unit and 17 real-Ghidra tests. Two builds produced an
identical 460,992-byte ZIP with SHA-256
`b2cb5c81e9a33367059dfdb50d4aa692c4bc6dea619167592655975b3133ba0f`.

## Limitations

Cryptographic signature verification, eFuse acquisition, ECDSA/other target
formats, and claims about live hardware configuration are intentionally absent.
T025 is next; its completion is followed by the mandatory ESP32-S3 full-flash
acceptance gate and explicit user approval before T026.
