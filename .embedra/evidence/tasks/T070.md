## 3. Analysis of Remaining Unreached Core Branches

Across all 81 classes in `io.github.rezabakhshi.embedra.core.*`, exactly 2 branches remain unreached out of 838 total branches. Both were subjected to rigorous code review and confirmed to be defensive, unreachable assertions:
1. **`Stm32DfuParser.java` Line 95** (`address >= ADDRESS_SPACE_END`):
   - Condition: `if (size == 0 || address >= ADDRESS_SPACE_END || size > ADDRESS_SPACE_END - address)`
   - Analysis: `address` is read via `cursor.u32()`, which yields an unsigned 32-bit integer in the range `[0, 0xFFFFFFFF]`. `ADDRESS_SPACE_END` is defined as `0x1_0000_0000L` (4 GiB). Therefore, `address` is mathematically guaranteed to be strictly less than `ADDRESS_SPACE_END`. The branch is an intentional defense-in-depth guard against prospective 64-bit address extensions, and cannot be triggered on 32-bit DFU images.
2. **`Stm32DfuParser.java` Cursor Line 182** (`size < 0`):
   - Condition: `if (size < 0 || size > end - position)`
   - Analysis: `size` is supplied internally by `Stm32DfuParser` using compile-time non-negative constants (`ELEMENT_HEADER_LENGTH = 8`, `TARGET_HEADER_LENGTH = 274`) or `cursor.u32()` unsigned integers. Negative sizes are impossible from internal callers. This is a private cursor contract assertion.
