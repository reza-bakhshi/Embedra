## 2. Test Architecture & Mutation Engine

The test suite is structured in `src/test/java/io/github/rezabakhshi/embedra/core/fuzz/`:

1. **`DeterministicMutationEngine`**:
   - High-throughput seeded deterministic mutator using `SplittableRandom`.
   - Generates 8 distinct mutation classes covering both structural and arithmetic edge cases:
     - `truncate`: Random truncation to any length between 0 and $N-1$ bytes.
     - `flipBytes`: Bit and byte flips (1 to 8 random bytes flipped with random XOR masks).
     - `randomBytes`: Unstructured pseudorandom byte streams of varying lengths (0 to 4,096 bytes).
     - `appendGarbage`: Trailing data corruption and suffix appending.
     - `injectBoundaryValues`: 32-bit boundary integer injections (`0`, `1`, `0xFF`, `0xFFFF`, `0x7FFFFFFF`, `0x80000000`, `0xFFFFFFFF`, `0xDEADBEEF`, `0xCAFEBABE`) at random offsets.
     - `zeroRange`: Splicing ranges of 4 to 32 zero bytes into the payload.
     - `duplicateChunk`: Repeating / duplicating interior chunks across offsets.
     - `invertBits`: Bitwise negation across multi-byte spans.
   - Special cases: Systematic evaluation of empty byte arrays (`new byte[0]`), single-byte inputs, and all `0xFF` inputs.
   - Outcome Digesting: Computes a canonical SHA-256 digest over the ordered outcome sequence of all 10,000 cases.

2. **Test Suites**:
   - `Esp32BinaryFormatFuzzTest`: 10,000 cases on `EspImageParser` and `EspAppDescriptionExtractor` (Seed: `0x0E53_2032_0001L`).
   - `Esp8266BinaryFormatFuzzTest`: 10,000 cases on `Esp8266ImageParser` covering both v1 (`0xE9`) and v2 (`0xEA`) formats (Seed: `0x8266_F022_0002L`).
   - `RpUf2BinaryFormatFuzzTest`: 10,000 cases on `RpUf2Parser` covering 512-byte blocks, family IDs, sequence flags, and payload lengths (Seed: `0x2040_2350_0003L`).
   - `Stm32DfuBinaryFormatFuzzTest`: 10,000 cases on `Stm32DfuParser` covering DfuSe prefix, target descriptor blocks, element records, and UFD suffix with CRC32 (Seed: `0xDF11_0483_0004L`).
   - `Stm32VectorDiscoveryBinaryFormatFuzzTest`: 10,000 cases on `Stm32VectorDiscovery` scanning raw Cortex-M vector tables against RAM ranges and Thumb execution targets (Seed: `0xF103_C800_0005L`).
   - `EspPartitionTableBinaryFormatFuzzTest`: 10,000 cases on `EspPartitionTableDiscovery` scanning for `0x50AA` magic and verifying MD5 checksum tables (Seed: `0xAA50_EBEB_0006L`).
   - `RpBootMetadataBinaryFormatFuzzTest`: 10,000 cases on `RpBootMetadataParser` covering RP2040 Boot2 checksum verification and RP2350 IMAGE_DEF tagged structures (Seed: `0xDEAD_BEEF_0007L`).
   - `T071BinaryFormatFuzzMasterSuiteTest`: Master suite asserting all 7 formats run at least 10,000 cases and aggregate $\ge 70,000$ cases with zero crashes.

## 3. Guarantees and Verification Criteria

### A. Zero Crashes (Fail-Closed Robustness)
- Across 70,000 inputs, zero unhandled runtime exceptions occurred:
  - `NullPointerException`: 0
  - `ArrayIndexOutOfBoundsException` / `IndexOutOfBoundsException`: 0
  - `NegativeArraySizeException`: 0
  - `BufferUnderflowException`: 0
  - `StackOverflowError`: 0
  - `OutOfMemoryError`: 0
- Every malformed rejection is typed and bounded:
  - `DiagnosticException` carrying structured `DiagnosticCode` (`ESP_*`, `ESP8266_*`, `RP_*`, `STM_*`, `CORE_*`, `LIMIT_EXCEEDED`).
  - Diagnostic source ranges are verified to never exceed the mutated input boundaries.

### B. Zero Hangs (Bounded Execution Time)
- All parsers enforce loop bounds and cooperative `CancellationToken` checks.
- Execution of all 10,000 cases per format completes in under 2.5 seconds (total 70,000 cases in $\approx 2.1$ seconds).

### C. Uncontrolled Allocation Protection
- Ingestion byte limits (`limits.maxInputBytes()`) and allocation caps (`limits.maxAllocationSize()`, `limits.maxObjects()`) prevent memory exhaustion from crafted large segment/target/block count fields.

### D. Zero Committed Partial State
- Pure parsers return immutable domain models or fail closed; no intermediate program transactions or filesystem mutations occur.

### E. Deterministic Reproducibility
- Seeded PRNG ensures bit-for-bit repeatability across independent runs, JDK builds, and host environments.
- In each test suite, the entire 10,000-case campaign is executed twice back-to-back; the resulting outcome SHA-256 digests match bit-for-bit.
