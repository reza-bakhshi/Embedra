# T054 Evidence — Official board profiles and Pico SDK/TinyUSB/lwIP/CYW43 metadata & signature enrichments

## Status

`COMPLETE` on 2026-10-03. T054 implements official board profiles and Pico SDK/TinyUSB/lwIP/CYW43 enrichments across `targets.rp`, `analyzers.rp`, and `ghidra.rp`:
- Official Board Profiles: Pico, Pico W, Pico 2, and Pico 2 W modeled in `RpBoardProfileEngine` over exact silicon parts (RP2040 and RP2350A) without mutating or conflating silicon identity (RP-008).
- Flash boundaries: 2 MiB QSPI on Pico and Pico W; 4 MiB QMI on Pico 2 and Pico 2 W. Bounded to 16 MiB maximum addressable flash.
- Wireless subsystems: CYW43439 over SPI and PIO bus interfaces on Pico W and Pico 2 W.
- Pin allocations: Immutable `RpPinAllocation` definitions for user LEDs (GPIO 25 on Pico/Pico 2) and wireless control pins (WL_ON, WL_REG_ON, WL_DATA, WL_CLK, WL_CS on Pico W / Pico 2 W).
- Fail-closed validation: Reject mismatched board/silicon pairings with `DiagnosticCode.RP_BOARD_MISMATCH`.
- Pico SDK Binary Info Parser (`RpBinaryInfoParser`): Pure bounded scanner for markers `0x7188dac3` and `0xe71aa39a`, traversing reverse pointers, zero-terminated lists, and extracting program name, version, build date, binary end, URL, description, SDK version, pico board, boot2 name, features, build attributes, pin allocations, and block devices under `ParserLimits` and `CancellationToken`.
- Component Detectors (`analyzers.rp`):
  - TinyUSB (`RpTinyUsbDetector`): Standard USB Device, Configuration, Interface, and Endpoint descriptor verification; core API signature detection (`tud_init`, `tud_task`, `tud_cdc_*`, `tud_msc_*`, `tud_hid_*`).
  - lwIP (`RpLwIpDetector`): Version string recovery (`lwIP vX.Y.Z`), protocol state model detection (TCP, UDP, DHCP, NETIF), and network stack API symbols (`lwip_init`, `netif_add`, etc.).
  - CYW43 (`RpCyw43Detector`): CYW43439 wireless driver symbol recovery, SPI vs PIO bus wrappers, firmware blob markers, and country code tables.
- Ghidra Enrichment Applicator (`RpEnrichmentApplicator`): In a single transaction (`GhidraProgramTransaction`), sets program options (`Embedra RP Board`, `Embedra Pico SDK`, `Embedra RP Components`) and adds bookmarks for binary info headers, board pinouts, SDK pins, block devices, and detected components with unique categories to prevent collisions. Preserves user-defined bookmarks and labels.
- Loader integration (`RpFirmwareLoader`, `RpFirmwareImportService`): Automatically discovers and applies Pico SDK binary info and components; accepts optional board profile selection; validates and resolves board configuration.
- Support states: All silicon records and board profiles remain `PLANNED` per RP-002 and STM-019.

## Scope and Invariants

- RP-008: Board profiles (`pico`, `pico_w`, `pico2`, `pico2_w`) never mutate silicon identity (always references `RP2040` or `RP2350A`).
- AN-010 / AN-011: Pure component analyzers operate over immutable `RpAnalysisContext` without depending on Ghidra runtime APIs.
- Parser limits and cooperative cancellation enforced across `RpBinaryInfoParser` and all detectors.
- Idempotent and non-destructive: re-importing or re-running does not corrupt or duplicate bookmarks or options.
