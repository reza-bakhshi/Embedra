# T099 Evidence — Nordic SoftDevice / MBR / Bootloader Discovery, Vector Relocation & Dual-Core Layout Analysis

## Status

`COMPLETE` on 2026-10-13. T099 implements pure Nordic Semiconductor SoftDevice, MBR,
and bootloader discovery, vector relocation analysis, and dual-core firmware layout partitioning.
The SoftDevice detector fingerprints Nordic wireless protocol stacks (S110, S112, S120, S130,
S132, S140), verifies Master Boot Record (MBR) presence at `0x00000000`, discovers application
vector table relocation offsets (`0x00019000` for S112, `0x00026000` for S132, `0x00027000` for S140),
relocates and aligns Cortex-M Thumb entry point vectors, extracts SVC handler addresses for
SoftDevice API table resolution, and inspects UICR configuration blocks to recover the target
bootloader address from `BOOTLOADERADDR` (`0x10001014`). The dual-core layout analyzer partitions
nRF5340 firmware memories into independent Application core (Flash at `0x00000000`, RAM at `0x20000000`)
and Network core (global Flash at `0x01000000`, global RAM at `0x21000000`) address spaces, validates
inter-processor communication channel counts, and classifies address spaces in accordance with
`Embedra-SpecKit.md` (T099, NRF-003, NRF-005, NRF-006, Section 8.3A, and Section 12).

## 1. Deliverables

1. **SoftDevice Domain Model & Detector**:
   - `src/main/java/io/github/rezabakhshi/embedra/targets/nordic/softdevice/NordicSoftDeviceType.java`:
     - Enumeration covering S110, S112, S120, S130, S132, S140, and UNKNOWN stacks.
   - `src/main/java/io/github/rezabakhshi/embedra/targets/nordic/softdevice/NordicSoftDeviceInfo.java`:
     - Immutable record capturing SoftDevice type, version string, FWID, base address (`0x00001000`),
       size, relocated application vector table offset, MBR presence flag, MBR size (`0x1000`),
       and SVC handler address.
   - `src/main/java/io/github/rezabakhshi/embedra/targets/nordic/softdevice/NordicSoftDeviceDetector.java`:
     - Pure analyzer providing:
       - `hasMbr`: Validates MBR vector table at `0x00000000` with SRAM initial SP and MBR reset vector.
       - `detect`: Fingerprints SoftDevice stack at `0x00001000`, identifies relocated application vector
         table offsets, and calculates SoftDevice size.
       - `hasValidApplicationVector`: Validates relocated Cortex-M initial SP in SRAM and odd Thumb reset vector.
       - `relocateApplicationVector`: Validates relocated vector table and returns aligned 32-bit entry address.
       - `discoverBootloaderAddress`: Inspects UICR registers (`0x10001014`) to discover bootloader entry address.

2. **Dual-Core Domain Model & Analyzer**:
   - `src/main/java/io/github/rezabakhshi/embedra/targets/nordic/dualcore/NordicDualCoreLayout.java`:
     - Immutable record holding partitioned address ranges for Application Core Flash/RAM and
       Network Core global/local Flash/RAM, along with IPC channel count.
   - `src/main/java/io/github/rezabakhshi/embedra/targets/nordic/dualcore/NordicDualCoreAnalyzer.java`:
     - Pure analyzer constructing verified dual-core layouts for nRF5340 parts, enforcing fail-closed
       rejection of single-core parts, and providing address classification helpers
       (`isApplicationCoreAddress` and `isNetworkCoreAddress`).

3. **Automated Unit Tests**:
   - `src/test/java/io/github/rezabakhshi/embedra/targets/nordic/NordicSoftDeviceDetectorTest.java`:
     - Tests MBR detection, S132 and S140 SoftDevice identification, application vector relocation,
       invalid vector rejection, and UICR bootloader address discovery.
   - `src/test/java/io/github/rezabakhshi/embedra/targets/nordic/NordicDualCoreAnalyzerTest.java`:
     - Tests partition layout creation for nRF5340, rejection of single-core parts, and address
       space classification.
