- The first implementation run exposed an incorrect OTA CRC complement model;
  the oracle was corrected against ESP-IDF and then passed.

- Focused tests cover all required handler kinds, redundant OTA records,

  FAT/filesystem restraint, custom/encrypted content, immutability, object

## Implementation

- `EspPartitionHandlerRegistry` dispatches encrypted, OTA state, PHY, NVS,
  coredump, NVS keys, FAT, SPIFFS, LittleFS, inactive-app, and custom content in
  a deterministic order.
- Each immutable inspection records handler kind, disposition, source range,
  bounded metadata, diagnostics, and sensitivity. Invalid enrichment remains
  non-fatal to a validated workspace.
- OTA selection applies ESP-IDF sequence/state/CRC semantics and refuses to
  select an absent or erased application slot.
- NVS values are not decoded, key bytes are never reported, coredumps are not
  executed, and configured filesystems are not guessed.
- Fully erased application slots are explicit artifacts; populated invalid
  application images remain fatal.
- ESP32-S3 RTC data uses the pinned half-open `0x50000000`–`0x50002000` range
  and is never executable in the Xtensa program.
