# T056 Evidence — Bounded multi-encoding and stack-string recovery

## Status

`COMPLETE` on 2026-10-04. T056 implements bounded multi-encoding string discovery and stack-constructed string recovery across ARM, RISC-V, and Xtensa architectures (AN-001):
- Multi-Encoding String Scanner (`analyzers.strings`):
  - Pure scanner over byte slices, memory blocks, and firmware images (`MultiEncodingStringScanner`, `ExtractedString`, `StringScanOptions`).
  - Supports ASCII, UTF-8 (strict RFC 3629 rejection of overlong sequences, surrogate halves, and invalid code points), UTF-16LE, UTF-16BE (zero-byte high/low ratio heuristic to reject binary noise), and Pascal length-prefixed formats (8-bit and 16-bit).
  - Filters false positives with configurable minimum length thresholds and printable ratio heuristics.
  - Distinguishes static string literal provenance (`STATIC_LITERAL`) with confidence scoring (`CONFIRMED`, `LIKELY`, `PLAUSIBLE`).
  - Implements sensitive content masking helper (`redactedContent()`) guaranteeing zero secret leaking in logs (AN-008).
- Stack-String Recovery Engine (`analyzers.strings.stack`):
  - Pure analyzer inspecting disassembled function instruction streams (`StackStringRecoveryAnalyzer`, `StackInstruction`, `RecoveredStackString`).
  - Emulates immediate loads into registers (`mov/movs/movw/movt/mvn/ldr` on ARM; `li/lui/addi/mv` on RISC-V; `movi/mov/addi/l32r` on Xtensa) and stack pointer aliasing (`r7/r11` on ARM; `s0/fp` on RISC-V; `a7/a15` on Xtensa).
  - Emulates immediate store idioms (`strb/strh/str` on ARM Thumb/Thumb-2; `sb/sh/sw` on RISC-V 32-bit; `s8i/s16i/s32i` on Xtensa LX6/LX7) to reconstruct contiguous stack frame byte buffers.
  - Decodes contiguous stack buffers into strings and attributes each string to its containing function, stack offset, decoded content, encoding, confidence, and instruction address span.
  - Distinguishes stack-constructed provenance (`STACK_CONSTRUCTED`).
- Ghidra String Annotation Applicator and Analyzer (`ghidra.strings`):
  - Transactional applicator (`GhidraStringApplicator`) executing in a single `GhidraProgramTransaction` (rolling back on error or cancellation).
  - Annotates discovered static strings with `Embedra Strings` bookmarks and EOL comments.
  - Annotates recovered stack strings with `Embedra Stack Strings` bookmarks and EOL comments on the first instruction in the construction span.
  - Populates program options under `Embedra String Analysis` (counts by encoding: ASCII, UTF-8, UTF-16LE, UTF-16BE, Pascal, and stack string counts).
  - Strictly preserves existing user labels, symbols, and bookmarks.
  - `EmbedraStringAnalyzer` extends Ghidra's `AbstractAnalyzer` for automated static and stack-string recovery across ARM, RISC-V, and Xtensa architectures.
  - Logs only aggregate counts to prevent sensitive string exposure in log files (AN-008).

## Scope and Invariants

- Strictly bounded execution under `ParserLimits` (max strings, max string length, max instruction depth per function) and `CancellationToken`.
- Do not alter or destroy existing user labels, symbols, or bookmarks.
- Pure analysis remains strictly separated from Ghidra Program DB mutation.
- String recovery differentiates provenance: `STATIC_LITERAL` vs `STACK_CONSTRUCTED` with confidence ranking (`CONFIRMED`, `LIKELY`, `PLAUSIBLE`).
- Zero secret leaking: secrets are never printed in plain text in logs (AN-008).
