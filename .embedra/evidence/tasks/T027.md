# T027 Evidence — Shared ESP Target Services

## Status

`COMPLETE` on 2026-09-24. T028 is next.

## Scope and requirements

- Requirements: Constitution III, IV, V, VII, and X; CORE-003, CORE-010,
  CORE-011, CORE-020; ESP-003 through ESP-005, ESP-017 through ESP-021;
  TOPO-001 through TOPO-006; specification sections 8.1, 10, and 12.1.
- Prerequisites: T001 through T026A and the approved ESP32-S3 application and
  full-flash gates.
- Specification SHA-256 was verified before editing. Restricted local firmware
  remained ignored, untracked, digest-gated, and outside package artifacts.

## Test-first evidence

`EspSharedTargetServicesTest` was added before production implementation. Its
first run failed compilation with 13 missing-symbol errors for the provider
contract, resolver, resolution, memory map/region, and entry validator. The
retained tests exercise exact chip-ID resolution, duplicate rejection,
RISC-V-neutral memory and alignment behavior, and evidence-backed ESP32-S3
topology construction.

## Implementation

- Added pure `EspTargetProvider`, `EspTargetResolver`, and
  `EspTargetResolution` contracts. Only implemented providers are registered;
  catalog records do not imply firmware support.
- Added `EspMemoryMap`, `EspMemoryRegion`, and `EspEntryPointValidator`.
  Provider-owned language, address-space, range, permission, and evidence data
  drive these services without ISA branches.
- Refactored `Esp32S3TargetProvider` to retain chip ID 9, language, memory map,
  evidence, provider identity, and topology while delegating structural work.
- Generalized the Ghidra mapper to `EspTargetProvider`; the import workflow
  resolves its provider and carries the resolved execution topology through
  GUI and headless results.
- Kept canonical report and program-snapshot serialization stable. Pack and
  FID applicability remain ESP32-S3-specific.
- Added ADR 0022 and updated architecture, README, and support claims without
  promoting any catalog-only device.

## Support boundary and limitations

ESP32-S3 remains the only implemented ESP target. The topology reports one
application CPU because current import fixtures prove that shape; it does not
claim complete physical dual-core, ULP, ROM-execution, or radio topology.
Additional Xtensa and RISC-V providers require independent fixtures, memory
maps, topology evidence, packs, and gates in T028 and T029. The common ESP
layer therefore remains provisional.
