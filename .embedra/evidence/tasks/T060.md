# T060 Evidence — Ranked Security Leads (Comparisons, Commands, Shells, OTA, and Authorization Branches)

## Status

`COMPLETE` on 2026-10-05. T060 implements ranked comparison, debug-command, shell, OTA, and authorization leads with clear heuristic confidence across ARM, RISC-V, and Xtensa architectures (AN-005, AN-006, AN-008):
- Pure Security Leads Domain Models (`analyzers.leads`):
  - `LeadCategory`: Classifies leads into `PASSWORD_TOKEN_COMPARISON`, `DEBUG_COMMAND`, `DEBUG_SHELL`, `OTA_ENDPOINT`, and `AUTHORIZATION_BRANCH`.
  - `LeadConfidence`: Heuristic confidence tiers (`HIGH`, `MEDIUM`, `LOW`) with rank and `fromScore()` helper.
  - `LeadSeverity`: Triage severity ranking (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFO`).
  - `HeuristicFactor`: Captures contributing rule identifiers, descriptions, and heuristic weights.
  - `SecurityLead`: Immutable record tracking lead ID, category, confidence tier, confidence score, severity, memory address, associated symbol, target operand/command/endpoint, human-readable description, contributing heuristic factors, structured metadata attributes, and secret redaction flag.
  - `SecurityLeadsReport`: Aggregated report with ranking (sorted descending by confidence score, severity, address), category/confidence/severity counters, and structured export to JSON, Markdown tables, and SARIF 2.1.0 with secret masking (`[REDACTED_SECRET]`) enabled by default (AN-008).
- Scanner Engines (`analyzers.leads.scanner`):
  - `ComparisonLeadScanner`: Disassembles function bodies across ARM Cortex-M Thumb, RISC-V 32, and Xtensa architectures. Resolves operands to known string comparisons (`strcmp`, `strncmp`, `strcasecmp`, `strncasecmp`), memory comparisons (`memcmp`, `bcmp`), constant-time cryptographic comparisons (`CRYPTO_memcmp`, `timingsafe_bcmp`, `mbedtls_ct_memcmp`), and custom authentication symbols. Detects sensitive keywords (`password`, `admin`, `secret`, `token`, `pin`, `key`, `auth`, `flag`). Lookahead detection inspects following instructions for immediate conditional branches (`cbz`, `cbnz`, `beq`, `bne`, `beqz`, `bnez`), producing linked `AUTHORIZATION_BRANCH` leads that identify gating decision paths.
  - `DebugCommandLeadScanner`: Scans memory and pointer tables for embedded CLI command table structures (`{ name, handler, help }` or `{ name, func }`) matching administrative and debug command keywords (`root`, `admin`, `debug`, `shell`, `su`, `factory`, `diag`, `backdoor`, `dump`, `reboot`, `erase`, `flash`, `unlock`, `poke`, `peek`). Detects interactive debug shell prompts (`# `, `shell> `, `cli> `, `debug> `, `admin> `, `esp> `) and corroborates them against console initialization symbols (`esp_console_init`, `microrl_init`, `embedded_cli_init`, `FreeRTOS_CLIInit`).
  - `OtaLeadScanner`: Scans strings and symbols for over-the-air firmware update endpoints: URL patterns with firmware extensions or update paths (`/ota`, `/update`, `/firmware`, `.bin`, `.hex`, `.pkg`, `.uf2`), MQTT update topics (`*/ota`, `*/firmware/update`), and references to OTA APIs (`esp_ota_begin`, `esp_https_ota`, `bootloader_common_ota_select`, `HAL_FLASH_Program`, STM32 DFU/IAP).
  - `SecurityLeadScanner`: Master scanner orchestrating comparison, command, shell, and OTA scanners under `ParserLimits` and `CancellationToken`.
- Ghidra Findings Annotation Applicator and Analyzer (`ghidra.leads`):
  - `EmbedraSecurityLeadAnalyzer`: Extends `AbstractAnalyzer` for automated program-wide discovery of candidate security leads.
  - `GhidraSecurityLeadApplicator`: Transactionally creates bookmarks under `Embedra Lead: <CATEGORY>`, adds non-destructive EOL comments (`[Lead: <CATEGORY> (<CONFIDENCE>)] <Description>`), and populates program options under `Embedra Security Leads`. Preserves existing user-defined symbols and bookmarks intact. Zero unmasked secrets are logged (AN-008).
  - `GhidraSecurityLeadApplicationReport`: Summary report of applicator actions.

## Scope and Invariants

- Bounded execution under `ParserLimits` (max objects, max input bytes, max scan depth) and `CancellationToken`.
- Treats findings as ranked leads, not verified facts (AN-005).
- Do not alter or destroy existing user labels, symbols, or bookmarks.
- Pure analysis remains strictly separated from Ghidra Program DB mutation (`ArchitectureBoundaryTest` verified).
- Distinguishes diagnostic severity and confidence tiers.
- Zero secret leaking: unmasked credentials or sensitive format parameters are never printed in plain text in logs or exports (AN-008).
