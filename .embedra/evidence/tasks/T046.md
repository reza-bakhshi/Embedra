# T046 Evidence — STM32 WB/WB0/WL/WBA wireless and network-core distinctions

## Status

`COMPLETE` on 2026-10-02. T046 adds a pure, evidence-gated STM32 wireless layer
in `targets/stm32/wireless`. `Stm32WirelessPlanner.compose` pairs the
digest-pinned T032 curated catalog part, T039 memory plan, T040 SVD
applicability entry, and T044 security record — plus the T045 workspace plan
for the dual-core parts — for one exact part without mutating any input, and
classifies the wireless scope from the pinned topology only:

- `STM32WB55RGV6` and `STM32WB15CCU6` are `NETWORK_CORE_PINNED`: the CPU2
  network processor is fed by an independently supplied coprocessor-firmware
  contract whose binding stays the pinned configuration-dependent
  C2BOOT/C2OPT/SBRV citation, whose communication windows are the pinned IPCC
  (`0x58000C00`) and HSEM (`0x58001400`) ranges, and whose per-core
  register-model link comes from the pinned T040 applicability review (the
  CM0P line for WB55; explicitly absent for WB15 with its pinned reason).
- The other eight WB/WB0/WBA/WL3 parts (WB05/WB07/WB09, WBA25/WBA52/WBA65,
  WL33/WL3R) are `SINGLE_APPLICATION_CORE`: the pinned topology declares one
  executable CPU core, no second core or coprocessor image is invented,
  radio-to-CPU memory attribution is explicitly
  `UNAVAILABLE_NO_PINNED_RADIO_MEMORY_ATTRIBUTION`, and the radio register
  model is deferred or unavailable per the pinned applicability status. For
  WB55 the reason `RADIO_REGISTERS_NOT_IN_PINNED_REGISTER_MODELS` is justified
  in-repository: both shipped `STM32WB55_CM4`/`STM32WB55_CM0P` register models
  were verified to contain no `RF`/`RADIO`/`BLE` peripheral while carrying
  IPCC and HSEM.

Every other curated part fails closed with `WIRELESS_FAMILY_OUT_OF_SCOPE`
(43 parts asserted). All 53 curated parts remain `PLANNED`; T039-T045
artifacts, device-data packs, vector behavior, board profiles, signature
packs, security domains, workspaces, and every support state are unchanged.
No Ghidra adapter is added (`NO_ADAPTER_PURE_PLAN_ONLY`): the separately
supplied CPU2 image has no pinned image bytes, so there is no complete
program pair, and the general T033-T036 importers remain the input path.

The repository builds 341 unit tests and 93 real-Ghidra integration tests,
and the STM32 Python suite reports 131 tests (`OK (skipped=4)`, the four
pre-existing optional pinned-source checks) plus 4 ESP Python tests. The
reproducible completion gate passes with two clean, uncached 22-action builds
and a byte-identical 4,335,725-byte extension ZIP, SHA-256
`462d3ddc99378a5ec7ef7fadf3892b413e6f4d02efcc2adb60f701c95c2bf364`.

## Scope and invariants

- The pure/adapter boundary holds. `Stm32WirelessRecord` and
  `Stm32WirelessPlanner` live under `targets.stm32.wireless`; they import
  `core`, `catalog`, `memory`, `security`, and `workspace` model classes only
  and never import a Ghidra API.
- STM-008/STM-014/STM-020/TOPO-005: network/physical cores, radio hardware,
  and separately supplied coprocessor firmware are distinguished only where
  the pinned evidence decides. The record never claims a radio register
  window, a wireless protocol state, a CPU2 image range, or FUS/radio-stack
  address facts; every radio register model is `UNAVAILABLE` or `DEFERRED`
  with a reason derived from the pinned applicability status.
- TOPO-001/TOPO-002: the network core reuses the pinned T039 node identity
  (role `Network Cortex-M0+`, `INDEPENDENT_IMAGE`), and the coprocessor
  binding state is `UNRESOLVED_CONFIGURATION_DEPENDENT` with the pinned
  release mechanism — never a resolved placement. No family, sibling, or
  wildcard inference exists anywhere in the composer.
- STM-019: every exact part keeps `PLANNED`; `supportState()` is `PLANNED`
  and composition never promotes.
- Per-core register tags project mechanically onto the pinned core labels
  (`CM4` to Cortex-M4, `CM0`/`CM0+` to Cortex-M0+, `CM33` to Cortex-M33). A
  resolved applicability entry with no review note for an unmapped core fails
  closed; a resolved entry whose pinned review names the gap (WB15's
  `DUAL_CORE_M4_SVD_AVAILABLE_M0P_DEVICE_LINE_ABSENT`) becomes an explicit
  `UNAVAILABLE` register model with that pinned reason.
- The composer's structure agreements fail closed: a two-core topology
  without the pinned T045 workspace (`WIRELESS_WORKSPACE_UNPINNED`), a pinned
  workspace on a single-core topology (`WIRELESS_WORKSPACE_INAPPLICABLE`),
  cross-input part mismatches (`WIRELESS_PART_MISMATCH`), ambiguous or
  unmapped per-core SVD tags, and an unknown workspace network slot.

## Implemented model

### `targets/stm32/wireless/Stm32WirelessRecord`

Immutable per-part record with series (WB/WB0/WBA/WL3 from the curated
family), status, `CoreRole` for the application core (pinned node identity
plus register-model state `SHIPPED`/`DEFERRED`/`UNAVAILABLE` and the pinned
per-core SVD file), `RadioSubsystem` (pinned management classification plus
register-model availability), `SharedResources` (for network-core parts, a
non-mutating pointer to the pinned T045 workspace that owns CPU1/CPU2 shared
banks, mailbox/semaphore windows, and the boot order; for single-core parts,
the explicit no-pinned-attribution state), an optional `NetworkCore` carrying
the pinned compilation/ISA/security identity, the pinned communication
windows, and the `CoprocessorFirmware` contract
(`INDEPENDENTLY_SUPPLIED`/`UNRESOLVED_CONFIGURATION_DEPENDENT`, the pinned
C2BOOT release mechanism, and the pinned `cpu2-fetch-view` unresolved view),
the pinned T044 security record reference, and four `VERIFIED_CHECKSUM`
evidence entries pinning the curated catalog, memory-plan, applicability, and
security-domain digests. The constructors reject blank identity, mismatched
parts, wrong firmware relationships, SHIPPED-without-file or
DEFERRED/UNAVAILABLE-with-wrong-file-or-reason, a network core without pinned
communication windows or with duplicated windows, ranges beyond the 32-bit
space, and an inconsistent status/shared-resource/workspace combination.

### `targets/stm32/wireless/Stm32WirelessPlanner`

`compose(catalogPart, plan, workspace, securityRecord, entry)` and
`evaluateNetworkCoreImage(plan, workspace, image)` fail closed with stable
`WIRELESS_*`/`BINDING_*` diagnostics:

`WIRELESS_PART_MISMATCH`, `WIRELESS_FAMILY_OUT_OF_SCOPE`,
`WIRELESS_WORKSPACE_UNPINNED`, `WIRELESS_WORKSPACE_INAPPLICABLE`,
`WIRELESS_CORE_ROLE_MAPPING_UNRESOLVED`,
`WIRELESS_CORE_ROLE_MAPPING_AMBIGUOUS`, `BINDING_PART_MISMATCH`,
`BINDING_WORKSPACE_UNPINNED`, `BINDING_IMAGE_EMPTY`,
`BINDING_IMAGE_OUT_OF_SPACE`, and `BINDING_RANGE_NOT_CPU2_ACCESSIBLE`.

`evaluateNetworkCoreImage` classifies a caller-supplied CPU2 image range
against pinned CPU2 memory attribution only: a range fully covered by
CPU2-attributed RAM (`sharedAccess` containing `cpu2`) is
`BINDABLE_UNRESOLVED_FETCH_VIEW` with the covering region ids and the pinned
fetch view; a range fully inside the pinned CPU1 FLASH image is
`FLASH_VIEW_CONFIGURATION_DEPENDENT`; partial coverage (for example crossing
a SRAM2B boundary), memory outside every attributed region, an empty or
oversized range, a non-MCU address space, and part/workspace mismatches fail
closed. No byte is placed and no fetch view is ever resolved.

### Ghidra adapter boundary

Applying wireless facts to Ghidra programs remains out of scope. The CPU2
image bytes are unpinned and the C2OPT/SBRV fetch basis is
configuration-dependent, so no adapter, no integration test, and no Ghidra
mutation are added; the pure records, the workspace references, and the
binding classification are the support a later task can build on. This
matches the T042/T044/T045 `NO_ADAPTER` precedent.

### Failures encountered and resolved

- The first composition family check ran after the per-core register
  projection, so a non-wireless part surfaced a role-mapping diagnostic
  instead of `WIRELESS_FAMILY_OUT_OF_SCOPE`; the family check now runs first
  and the 43-part sweep asserts the correct diagnostic.
- The record initially forbade a pinned SVD file on a `DEFERRED` register
  model, contradicting the reviewed T040 state (a deferred line has an
  identified file); the constructor now requires the file for a deferred
  model and forbids it only for `UNAVAILABLE`.
- WB15's network core initially failed closed on its absent CM0P line; the
  resolved-entry rule now honors a pinned review reason as an explicit
  `UNAVAILABLE` and still fails closed when no reason exists.
- Two checkstyle `EmptyLineSeparator` violations in the new test file were
  repaired; the checks now pass.

## Preserved boundaries and limitations

- T039 memory plans (`00def2817b…`), the curated catalog (`afc66a47…`), the
  T040 applicability artifact (`be795ab0…`) and device-data packs, T041 vector
  behavior, T042 board profiles, T043 signature packs, T044 security domains
  (`08da45f5…`), and the T045 workspace layer are unchanged.
- All 53 curated parts remain `PLANNED`; T046 promotes no support state.
- The radio register models of all ten wireless parts are unavailable or
  deferred with pinned reasons; the RF/RADIO/BLE/MRSUBG peripherals have no
  shipped register address or field data anywhere in this repository.
- The coprocessor firmware bytes are never loaded, placed, or bounded; the
  binding evaluator classifies caller-supplied ranges and always keeps the
  fetch view configuration-dependent.
- No separate Ghidra program is created for CPU2, and no radio-hardware
  execution unit is modeled as a disassembly target; the WB0/WL3 and WBA
  radio subsystems stay identity-classified only.
