# T052 Evidence — RP2040 ARMv6-M language, dual-core startup, XIP, boot2, vector-table, SRAM, ROM, peripheral, atomic-alias, and two-PIO-block provider data

## Status

`COMPLETE` on 2026-10-03. T052 implements comprehensive RP2040 target provider data and architecture modeling under `targets.rp`:
- Architecture & language: dual ARM Cortex-M0+ cores (`ARM:LE:32:Cortex`).
- Dual-core startup: Core 0 launches Core 1 via SIO FIFO (`0xD0000050`) and 32 hardware spinlocks (`rp2040.core0_launches_core1`).
- Memory regions: external flash XIP (`0x10000000`), XIP maintenance window (`0x14000000`), 264 KiB multi-bank SRAM (striped at `0x20000000` plus non-striped alias at `0x21000000`), 16 KiB internal boot ROM (`0x00000000`), standard peripherals (`0x40000000`), and atomic bus aliases (`0x50000000`).
- Boot2 validation: first 256 bytes of external flash with CRC-32 checksum.
- Vector table: 48 entries at `0x10000100` (16 ARM core exception vectors + 32 user IRQs).
- Atomic register access aliases: `Rp2040AtomicAlias` modeling NORMAL, XOR (`+0x1000`), SET (`+0x2000`), and CLEAR (`+0x3000`) apertures.
- Boot ROM: `Rp2040Rom` modeling 16 KiB ROM, magic bytes (`'M'`, `'u'`, 1), and lookup function table (`popcount32`, `memset`, `memcpy`, flash operations).
- Two PIO blocks: `pio0` (`0x50200000`) and `pio1` (`0x50300000`), each with 4 state machines, 32-word instruction memory, 4-word FIFO depth, and dedicated IRQs.
- Execution topology: symmetric CPU cores, BootROM, PIO0 and PIO1 programmable coprocessors, SIO inter-core communication links, and PIO interrupt links.
- Pure/adapter boundary maintained: all models and providers stay pure under `targets.rp` without importing Ghidra APIs.
- All silicon support states remain `PLANNED` per RP-002 and STM-019.
