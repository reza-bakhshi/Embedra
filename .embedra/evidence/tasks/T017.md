## Implementation

- `EspApplicationImportService` is the single loader workflow for interactive
  and `analyzeHeadless` callers. It has no caller-mode branch and returns the
  committed import report, optional metadata/diagnostics, canonical report,
  and canonical mapping snapshot.
- Canonical output retains input/provider digests, validations, mappings,
  permissions, metadata, entry symbol, source ranges, and mapped-byte digests,
  while excluding program names, host paths, timestamps, locale, time zone,
  and caller identity.
- The application loader delegates mutation and report construction to the
  shared service.
- A fixed seed drives 512 bounded truncation, byte-flip, random-byte, and
  trailing-byte cases. Each case either produces a complete immutable image or
  a typed bounded diagnostic. The exact reviewed outcome digest is
  `8f35791f21d7f0b875d7c094657a768ba29aa38a725dda13242474242a113d23`.
