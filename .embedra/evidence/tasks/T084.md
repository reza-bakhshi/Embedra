# T084 Evidence — Target-Aware Full-Flash Capture Identification and Workspace Planning for RISC-V ESP Targets

## Status

`COMPLETE` on 2026-10-13. T084 implements and independently verifies the pure full-flash
planning path for all 8 cataloged RISC-V ESP series (`ESP32-C3`, `ESP32-C2`, `ESP32-C5`,
`ESP32-C6`, `ESP32-C61`, `ESP32-H2`, `ESP32-H21`, `ESP32-H4`). Each target has an
independent `EspRiscVFlashLayoutProvider` with pinned chip IDs, bootloader start at `0x0000`,
partition table offset rules, 64 KiB MMU page size, and RISC-V language binding
(`RISCV:LE:32:default`). No RISC-V target inherits another target's flash layout or
processor assumptions, and all behaviors are verified against independent oracles.

## 1. Deliverables

1. **RISC-V Flash Layout Providers**:
   - `EspRiscVFlashLayoutProvider` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/EspRiscVFlashLayoutProvider.java`):
     - Implements `EspFlashLayoutProvider` with target-specific profiles:
       - `ESP32-C3`: chip ID 5, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-C2`: chip ID 12, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-C5`: chip ID 23, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-C6`: chip ID 13, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-C61`: chip ID 20, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-H2`: chip ID 16, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-H21`: chip ID 25, language `RISCV:LE:32:default`, compiler `gcc`.
       - `ESP32-H4`: chip ID 28, language `RISCV:LE:32:default`, compiler `gcc`.
     - Validates chip ID in bootloader and application headers, reporting `DiagnosticCode.ESP_CHIP_MISMATCH` on mismatch.
   - `EspFlashLayoutRegistry`:
     - Registers all 8 RISC-V layout providers in the defaults registry.
     - Lookups by chip ID and series name resolve the target provider directly.

2. **Full-Flash Planning Integration**:
   - Candidate bootloader discovery in `EspFullFlashWorkspacePlanner` accurately detects
     the chip ID at candidate offset `0x0000` and resolves the target layout provider.
   - Full-flash workspaces extract:
     - Bootloader at offset `0x0000` with target-matched chip validation.
     - Partition table at `0x8000` (or `0x10000` for custom offset).
     - Factory and OTA application executables.
     - Data partitions, NVS, PHY, and encrypted assets as labeled non-program partitions.

3. **Automated Verification**:
   - `EspRiscVFullFlashTest` (`src/test/java/io/github/rezabakhshi/embedra/formats/esp/EspRiscVFullFlashTest.java`):
     - Validates layout profiles for all 8 RISC-V targets.
     - Plans `default-factory.bin` for each target and verifies executable roles and offsets.
     - Verifies automatic header detection and layout provider resolution.
     - Verifies custom table offsets and encrypted OTA slots.
     - Verifies rejection of corrupted partition MD5 checksums and wrong chip IDs.
