## Implementation and verification

- Independent closed v1 schemas define ROM and peripheral content. The normal
  manifest retains exact device, source URI/revision, license, transformation,
  redistribution state, file descriptors, and aggregate digest.
- Integrity, limits, cancellation, exact pack/content kind, exact device, and
  source-revision agreement are validated before immutable models are exposed.
- Ghidra application creates separate uninitialized ROM/peripheral views with
  conservative permissions, imported ROM functions/data symbols, peripheral
  aliases, and 32-bit register data. Existing memory, primary user names,
  functions, instructions, and types are preserved as deterministic conflicts.
- Reapplication creates no duplicates. Receipt-scoped removal deletes only
  created artifacts and refuses changed or user-bearing blocks. Pack identities
  and digests are retained in program options.
- The final clean run passed 118 unit and 17 real-Ghidra integration tests.
  Two complete builds produced byte-identical 408330-byte extension ZIPs with
  SHA-256
  `3d261bfaa9477247c94682229a225c61855aa2a1da15a7530f9e92dc082ad36c`.
  Exact pack entries are present; restricted dump bytes and host paths are absent
  from the outer and source ZIPs. Full results are retained in `commands.jsonl`.

## Limitations

The common ROM pack intentionally excludes mutually conflicting optional BLE
overlay/test linker scripts. Peripheral bit fields/enums, exact chip-revision
auto-selection, GUI action wiring, complete exact variant catalogs, and hardware
verification are not claimed. T023 is the exact next task.
