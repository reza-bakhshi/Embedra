## Implemented device-data transformation

### Exact-part applicability (no family or wildcard inference)

`catalogs/stm32/2026-09-29/svd-applicability.json` (SHA-256
`be795ab0d0d5da1b218428361690753fb39e8f962b3de8c160ae9a43d7970518`) resolves
all 53 curated exact parts. A part maps to an SVD device line only by an exact
device-name prefix or a named review override; any device name containing a
wildcard `X` is rejected, and a neighbouring line is never substituted.

- 8 parts are `EXACT_SVD_SHIPPED` across 7 device lines.
- 37 parts are `EXACT_SVD_DEFERRED` (exact line identified, pack not shipped in
  T040; no support promotion).
- 8 parts are `UNAVAILABLE` with a reason (for example `STM32F207ZGT6`,
  `STM32H553ZGT6`, `STM32U3C5ZIT6Q`, `STM32WBA25CEU7`, `STM32WBA65RIV7`,
  `STM32WL3RKBV6`; `STM32U5G9*` is present only as the wildcard `STM32U5Gx`).
- `STM32WB55RGV6` is reviewed to the per-core `STM32WB55_CM4` and
  `STM32WB55_CM0P` SVD files; `STM32WB15CCU6` to `STM32WB15_CM4` (its M0+
  device line is absent and not invented).

`Stm32SvdApplicability` verifies the artifact digest and the pinned curated
selection before exposing entries.

### Pure SVD model and generator

The `svd` boundary gains an immutable STM32 model (`Stm32SvdDevice`,
`Stm32SvdPeripheral`, `Stm32SvdRegister`, `Stm32SvdField`,
`Stm32SvdEnumeratedValue`, `Stm32SvdInterrupt`) that detects ambiguous interrupt
names, alternate views, and invalid widths.

`scripts/generate-stm32-svd-packs.py` deterministically transforms pinned SVD
files. It expands `derivedFrom` inheritance (peripheral, register, field,
enumerated values), `dim`/`dimIndex` arrays, and nested clusters; retains
alternate registers/groups and field read side effects; validates register
widths, field/register containment, and enumeration fit; and rejects malformed
XML, DTD/entities, oversized input, unresolved/cyclic inheritance, overlapping
fields, and unsupported constructs (`writeConstraint`,
`modifiedWriteValues`) instead of guessing.

Each manifest records the exact pack ID, supported exact parts, content digest,

redistribution, pack identity, closed-schema, and integrity mismatches.
`Stm32BundledPacks` fails closed when a shipped entry's pack is unavailable.

### Ghidra application

`Stm32SvdApplicator` applies a verified pack inside one rollback-capable
transaction:

- volatile, read/write, non-executable peripheral blocks (existing blocks are
  preserved with `MEMORY_PRESERVED`);
- qualified `IMPORTED` register labels (existing names and user primary symbols
  are preserved with `NAME_CONFLICT`);
- field-aware `StructureDataType` bit fields and `EnumDataType` field values
  under `/Embedra/<part>/SVD`, namespaced `Embedra STM32 SVD` comments;
- one `<part>_IRQn` `EnumDataType` per exact part under
  `/Embedra/<part>/Interrupts`, plus `Embedra STM32 Interrupts` provenance;
- deterministic conflicts (`TYPE_PRESERVED`, `ALTERNATE_VIEW_PRESERVED`,
  `INSTRUCTION_PRESERVED`) and idempotent reapplication.

Interrupt definitions are data types and provenance only; no vector labels,
functions, or core exception structures are created (T041).

### Interrupt device data

`Stm32InterruptPlan` exposes exact-part interrupts from the digest-pinned
curated catalog: 51 parts are `MAPPED_SINGLE` and applicable; `STM32N657X0H3Q`
(`CONDITIONAL_REVIEW`) and `STM32WL3RKBV6` (`MAPPED_VARIANTS`) remain explicit
and apply nothing.

## Hardening addendum — 2026-10-02

An independent T039–T041 review found four T040 hardening gaps; all were fixed
before T042 began.

1. `generate-stm32-svd-packs.py` rejected DTD/entities with a raw byte substring
   that UTF-16/UTF-32 input bypasses, and entity expansion ran before the
   complexity budget. Reproduced: a UTF-16 document with an internal entity
   parsed and expanded. `ensure_safe_xml` now strips an optional UTF-8 BOM,
   rejects UTF-16/UTF-32 BOMs and NUL-bearing heads, decodes UTF-8 strictly, and
   scans decoded text before parsing. UTF-16 regressions added.
2. `Stm32SvdPackLoader.peripheral` converted interrupt values outside the try, so
   an out-of-range value escaped as unchecked `ArithmeticException`;
   `Stm32InterruptPlan.load` had the same gap. Both now yield a typed
   `PACK_CONTENT_INVALID`/`IOException`, with a loader regression.
3. `Stm32SvdRegister` now rejects overlapping fields and duplicate field names,
   and `Stm32SvdField` rejects duplicate enumerated value names, so the loader
   no longer depends on the generator for those invariants. Model regressions
   added.
4. `Stm32SvdApplicator` now refuses to apply a pack or interrupt entry when the
   program records a different exact STM32 part (raw import, SVD, interrupt, or
   vector-label provenance). Regression added.

The shipped packs, the applicability digest
`be795ab0d0d5da1b218428361690753fb39e8f962b3de8c160ae9a43d7970518`, and all
support states are unchanged. Full details:
`.embedra/evidence/tasks/T039-T041-hardening.md`.
