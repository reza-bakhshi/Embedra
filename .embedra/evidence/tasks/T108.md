# T108 Evidence — Implement Atmel/Microchip ATDF / SVD Peripheral Packs, I/O Ports, Fuses & Schema Transforms

## Status

`COMPLETE` on 2026-10-16. T108 implements authoritative Atmel / Microchip peripheral register definition packs,
I/O port bitfield definitions, fuse bit maps, and schema transforms across 8-bit AVR microcontrollers
(classic megaAVR, classic tinyAVR, and modern AVR-Dx) and 32-bit ARM SAM microcontrollers (SAMD, SAME, SAMS, SAMV, SAM3)
under shared `ParserLimits` and `CancellationToken`, strictly isolated from other families.
The peripheral register packs enforce physical address space isolation (`DATA` for classic AVR I/O space and
`PERIPHERAL` for SAM 32-bit memory maps), non-overlapping bitfields, bounded resource limits, cooperative cancellation,
and cryptographic SHA-256 integrity verification against schema `"urn:embedra:schema:atmel-peripheral-pack:1"`
in accordance with `Embedra-SpecKit.md` (T108, ATMEL-005, ATMEL-008, ATMEL-009, Section 8.3B, and Section 12).

## 3. T108 remediation — modern AVR I/O port derivation (2026-10-16)

An independent review of the committed T108 packs found that `ioPorts` was empty for
every modern AVR part (AVR-Dx `AVR128DA48`, `AVR128DB48`, `AVR64DA32`, `AVR32DA28`,
and modern tinyAVR `ATtiny1614`). Cause: `atdf_io_ports()` matched `PORTx` instance
names in the classic `PORTx`/`DDRx`/`PINx` branch before evaluating the modern
`DIR`/`OUT`/`IN` branch, so the register-set check silently failed and the `elif`
was never reached for `PORTx`-named instances. No test asserted modern-AVR ports,
so the defect escaped the original verification.

1. Fix: `scripts/generate-atmel-packs.py` `atdf_io_ports()` now includes the classic
   register triple inside the first condition and falls through to the modern
   `DIR`/`OUT`/`IN` derivation when the classic triple is absent.
2. Regeneration: all 24 packs were regenerated from the same pinned sources
   (all eight `.atpack` archives re-verified against their pinned SHA-256 digests).
   A semantic diff confirmed that only the `ioPorts` key changed in the five affected
   packs; the other 19 packs are byte-identical apart from their regenerated checksums.
3. New derived facts: `AVR128DA48`/`AVR128DB48` expose `PORTA`–`PORTF` (8-pin each);
   `ATtiny1614` exposes `PORTA`, `PORTB`; `AVR64DA32`/`AVR32DA28` expose
   `PORTA`, `PORTC`, `PORTD`, `PORTF`; each port references its `DIR`/`OUT`/`IN`
   register triple from the same pack.
4. Regression coverage:
   - `scripts/tests/test_atmel_packs.py::test_modern_avr_io_ports_are_derived`
     asserts the exact AVR-Dx, 28/32-pin, and ATtiny1614 port sets.
   - `AtmelPeripheralPackTest.java::testModernAvrIoPortsAreDerivedFromDirOutInTriples`
     loads the registry packs and asserts port count, pin count, register triple,
     and per-port register resolution.
