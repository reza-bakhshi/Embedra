# T059 Evidence — Logging, assert, panic recovery, and format-to-call-site linkage

## Status

`COMPLETE` on 2026-10-05. T059 implements embedded logging, assert, panic recovery, and format-to-call-site linkage across ARM, RISC-V, and Xtensa architectures (AN-004, AN-006, AN-008, AN-010):
- Pure Diagnostic Logging Models (`analyzers.logging`):
  - Domain models:
    - `DiagnosticLogLevel`: Severity ordering (`PANIC`, `ASSERT`, `ERROR`, `WARNING`, `INFO`, `DEBUG`) and criticality helper (`isCritical()`).
    - `FormatArgumentType`: Inferred format argument types (`STRING`, `INTEGER`, `HEX_INTEGER`, `POINTER`, `FLOAT`, `CHARACTER`, `CUSTOM`, `UNKNOWN`).
    - `FormatSpecifier`: Typed descriptor capturing specifier index, raw text (e.g. `%02X`, `%1$s`), width, precision, and positional index.
    - `FormatStringDescriptor`: Encapsulates parsed format string raw text, specifiers list, total expected argument count, and ordered expected argument types.
    - `LoggingCallSite`: Immutable record tracking call instruction address, target function address/symbol, log level, format string descriptor, argument references (`file`, `line`, `expression`, `message`, `tag`), confidence (`CONFIRMED`, `LIKELY`, `PLAUSIBLE`), and human-readable explanation.
    - `LoggingAnalysisReport`: Aggregated report with grouping by log level, and structured export to JSON, Markdown tables, and SARIF 2.1.0 with secret masking enabled by default (`toJson(true)`, `toMarkdown(true)`, `toSarif(true)`).
- Format String and Assert Scanner Engines (`analyzers.logging.scanner`):
  - `FormatStringParser`: Pure parser identifying standard C and POSIX printf-style specifiers (`%s`, `%d`, `%i`, `%u`, `%x`, `%X`, `%p`, `%f`, `%c`), variable width/precision (`*`), length modifiers (`hh`, `h`, `l`, `ll`, `z`), literal percent (`%%`), and positional indexing (`%1$s`) under `ParserLimits`.
  - `AssertPanicPatternMatcher`: Identifies embedded assert and panic idioms across architectures:
    - Known function symbols: `assert`, `__assert`, `__assert_func`, `__assert_fail`, `configASSERT`, `panic`, `hard_assert`, `abort`, `esp_system_abort`, `assert_param`.
    - Heuristics: source file paths (`.c`, `.cpp`, `.h`, `.hpp`), valid line numbers (1..500000), and condition expressions (`!=`, `==`, `NULL`, `0`).
    - Termination instruction traps: ARM (`bkpt`, `udf`, `b .`), RISC-V (`ebreak`, `unimp`, `j .`), and Xtensa (`break.n`, `ill`, `j .`).
- Call-Site Linkage Engine (`analyzers.logging.linkage`):
  - `CallSiteArgumentResolver`: Inspects function disassembly backwards within a bounded window (default 32 instructions) leading to call instructions (`bl`/`blx` in ARM; `call`/`jal`/`jalr` in RISC-V; `call0`/`call4`/`call8`/`call12` in Xtensa).
  - Multi-architecture calling convention argument tracking:
    - ARM AAPCS: tracks `r0-r3` registers (immediate loads via `mov/movs/movw/movt`, PC-relative literal loads via `ldr/adr`).
    - RISC-V 32: tracks `a0-a7` registers (immediate loads via `li`, `lui + addi`, `la/lla`).
    - Xtensa: tracks call0 `a2-a7` registers and windowed `call4/call8/call12` caller argument registers.
  - Resolves pointer constants against the program's static string dictionary and links format strings and arguments to call sites.
- Ghidra Findings Annotation Applicator and Analyzer (`ghidra.logging`):
  - `GhidraLoggingApplicator`: Executes inside a single `GhidraProgramTransaction` (rolling back cleanly on error or cancellation).
  - Annotates discovered diagnostic call sites with `Embedra Logging: <LEVEL>` bookmarks (e.g. `Embedra Logging: PANIC`, `Embedra Logging: ASSERT`, `Embedra Logging: ERROR`, `Embedra Logging: WARNING`, `Embedra Logging: INFO`, `Embedra Logging: DEBUG`).
  - Emits non-destructive EOL comments (`[Log: <LEVEL>] <FormatString> (<File>:<Line>)`).
  - Populates program options under `Embedra Logging Analysis` (`Total Logging Call Sites`, `Panic Count`, `Assert Count`, `Error Count`, `Warning Count`, `Info Count`, `Debug Count`).
  - Strictly preserves existing user labels, symbols, and bookmarks.
  - `EmbedraLoggingAnalyzer`: Extends Ghidra's `AbstractAnalyzer` for automated function disassembly logging and assert recovery.
  - Logs only aggregate counts to prevent sensitive credential exposure in log files (AN-008).

## Scope and Invariants

- Strictly bounded execution under `ParserLimits` (max objects, max input bytes, max scan depth) and `CancellationToken`.
- Do not alter or destroy existing user labels, symbols, or bookmarks.
- Pure analysis remains strictly separated from Ghidra Program DB mutation (`ArchitectureBoundaryTest` verified).
- Distinguishes diagnostic severity: `PANIC`, `ASSERT`, `ERROR`, `WARNING`, `INFO`, `DEBUG`.
- Zero secret leaking: unmasked credentials or sensitive format parameters are never printed in plain text in logs or reports (AN-008).
