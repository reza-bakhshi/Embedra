# T083 Evidence — Target-Aware Full-Flash Capture Identification and Workspace Planning for ESP32 and ESP32-S2

## Status

`COMPLETE` on 2026-10-13. T083 implements target-aware capture identification, bootloader
boundary validation, bounded partition discovery, image and entry-point validation, and
artifact classification for original ESP32 and ESP32-S2. Bootloader start offsets (`0x1000`
for ESP32; `0x0000` for ESP32-S2) and chip IDs (`0` and `2`) are strictly validated.
Ambiguous inputs or mismatched chips are cleanly detected and rejected, and all behaviors
are verified against independent official-tool oracles.

## 1. Deliverables

1. **Target-Aware Flash Layout Providers**:
   - `Esp32FlashLayoutProvider` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/Esp32FlashLayoutProvider.java`):
     - Profile pins series `ESP32`, chip ID 0, Xtensa ISA (`EspCpuIsa.XTENSA`), language
       `Xtensa:LE:32:default`, bootloader starting offset `0x1000`, partition table offset
       `0x8000`, MMU page size 64 KiB, max flash size 16 MiB.
     - Validates bootloader and application images against chip ID 0.
   - `Esp32S2FlashLayoutProvider` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/Esp32S2FlashLayoutProvider.java`):
     - Profile pins series `ESP32-S2`, chip ID 2, Xtensa ISA (`EspCpuIsa.XTENSA`), language
       `Xtensa:LE:32:default`, bootloader starting offset `0x0000`, partition table offset
       `0x8000`, MMU page size 64 KiB, max flash size 16 MiB.
     - Validates bootloader and application images against chip ID 2.
   - `EspFlashLayoutRegistry`:
     - Registers both providers in the defaults registry and exposes them for dynamic resolution.

2. **Full-Flash Planning Integration**:
   - Candidate bootloader discovery in `EspFullFlashWorkspacePlanner` accurately distinguishes:
     - Dumps with bootloader at `0x1000` (original ESP32).
     - Dumps with bootloader at `0x0000` (ESP32-S2 and ESP32-S3).
   - Validates that the pre-bootloader region (`0x0000..0x1000`) on ESP32 is treated appropriately
     and not parsed as a corrupted image header.
   - Preserves separate programs for bootloader and factory/OTA applications.
   - Retains encrypted assets and data partitions as labeled non-program artifacts.

3. **Automated Verification**:
   - `Esp32AndS2FullFlashTest` (`src/test/java/io/github/rezabakhshi/embedra/formats/esp/Esp32AndS2FullFlashTest.java`):
     - Tests planning of `default-factory.bin` for ESP32 and ESP32-S2, verifying role and offsets.
     - Tests automatic header detection and layout provider resolution.
     - Tests custom table offset (`0x10000`) and OTA encrypted slot handling.
     - Tests rejection of corrupted MD5 trailers (`invalid-partition-md5.bin`) and wrong chip IDs (`malformed-wrong-chip.bin`).
