# T063 Evidence — Bounded Local Scanner-Plugin API and Adversarial Plugin Testing

## Status

`COMPLETE` on 2026-10-09. T063 implements a stable local scanner-plugin contract with strict resource boundaries, declarative pattern matching, JSON schema validation, Ghidra program integration, and comprehensive adversarial defense testing (AN-009, AN-006, AN-008):
- Pure Scanner Plugin Domain Models and Contracts (`analyzers.plugins`):
  - `ScannerPlugin`: Public SPI and execution contract for user-defined and declarative scanner plugins.
  - `PluginCapability`: Supported scan capabilities (`BYTE_SCAN`, `STRING_SCAN`, `METADATA_SCAN`).
  - `PluginType`: Underlying implementation classification (`DECLARATIVE_RULE`, `JAVA_CLASS`).
  - `DeclarativeMatcherType`: Matcher evaluation modes (`REGEX`, `HEX_BYTES`, `EXACT_STRING`, `ENTROPY`).
  - `PluginResourceBudget`: Bounded per-execution resource limits enforcing `maxWallTimeMs` (10 to 60,000 ms), `maxMemoryBytes`, and `maxFindings` (1 to 50,000).
  - `DeclarativeRuleDefinition`: Immutable rule configuration capturing rule ID, description, matcher kind, pattern, severity, confidence, normalized confidence score (0.0 to 1.0), secret flag, category, subcategory, and optional entropy bounds.
  - `ScannerPluginManifest`: Schema-validated (`urn:embedra:schema:scanner-plugin-manifest:1`) immutable manifest model with strict path traversal rejection (`..`, `/`, `\`), capability validation, and rule integrity.
  - `PluginManifestJsonParser`: Dedicated bounded JSON parser enforcing `ParserLimits` (input size, allocation, nesting depth, object count, wall time) and cooperative cancellation while supporting integer and floating-point parameters without leaking exceptions.
  - `ScannerPluginFinding`: Finding record capturing location, matched target, severity, confidence, secret status, and structured attributes; provides `toUnifiedFinding()` and secret masking (`maskedTarget(true)`) (AN-008).
  - `PluginScanContext`: Encapsulates binary data, base address, extracted strings, program metadata, platform identity, resource budget, and cancellation token.
  - `DeclarativeScannerPlugin`: Safe scanner executing regexes (with ReDoS input length bounds), hex byte patterns, exact strings, and Shannon entropy analysis over memory windows under cooperative cancellation.
  - `PluginExecutionStatus`: Standardized outcomes (`SUCCESS`, `TIMEOUT`, `LIMIT_EXCEEDED`, `CANCELLED`, `EXECUTION_ERROR`, `RESOURCE_EXHAUSTED`).
  - `ScannerPluginExecutionResult`: Execution outcome record capturing plugin ID, status, findings, wall-time duration, bytes scanned, and diagnostic messages.
  - `ScannerPluginRunner`: Sandboxed runner using isolated worker threads with strict timeout termination via `Future.get()`, thread interruption, `Throwable` containment (trapping `OutOfMemoryError`, `StackOverflowError`, and uncaught runtime exceptions), cooperative cancellation checks, and finding count capping.
  - `ScannerPluginRegistry`: Thread-safe registry supporting programmatic registration, JSON manifest file loading, directory discovery, duplicate rejection, platform filtering, and batch execution.
  - `ScannerPluginBatchReport`: Aggregates multi-plugin execution results, counters, durations, flattened `UnifiedFinding` records, and export to JSON and Markdown with secret masking.
- JSON Schema Definition (`schemas/plugin/scanner-plugin-manifest-v1.schema.json`):
  - Draft 2020-12 closed schema (`urn:embedra:schema:scanner-plugin-manifest:1`) with `additionalProperties: false`, path traversal pattern enforcement, and resource limit ranges.
  - Integrated into `SchemaResourcesTest`.
- Ghidra Plugin Integration (`ghidra.plugins`):
  - `GhidraScannerPluginExtractor`: Extracts initialized memory bytes, defined strings, and metadata from a live Ghidra `Program` into a `PluginScanContext` under `ParserLimits` and cancellation.
  - `GhidraPluginApplicator`: Persists plugin findings into Ghidra bookmarks (`Embedra Plugin: <PluginId>`) with category `CUSTOM_PLUGIN` and updates program options (`Embedra Plugin Analysis`) in a transactional boundary (`GhidraProgramTransaction`).
  - `EmbedraPluginAnalyzer`: Automated Ghidra byte analyzer with configurable plugin directory, timeout, and max finding options.
  - Synchronizer integration: `GhidraFindingBookmarkSynchronizer` maps `Embedra Plugin: *` bookmarks to `FindingCategory.CUSTOM_PLUGIN`.
- Adversarial and Unit Verification (`analyzers.plugins`, `ghidra.plugins`):
  - `ScannerPluginManifestTest`: Schema conformance, invalid schema ID, extra fields, unsafe path traversal, invalid semver, and out-of-range limits.
  - `DeclarativeScannerPluginTest`: Regex, hex bytes, exact strings, Shannon entropy windows, finding count capping, and cooperative cancellation.
  - `ScannerPluginRegistryTest`: Programmatic registration, JSON string/file loading, directory discovery, platform filtering, and unregistration.
  - `AdversarialScannerPluginTest`:
    - Infinite loop / thread hang timeout containment within configured budget.
    - ReDoS catastrophic backtracking defense.
    - `OutOfMemoryError` trap returning `RESOURCE_EXHAUSTED` without JVM crash.
    - `StackOverflowError` trap returning `EXECUTION_ERROR`.
    - Excessive finding flood capped at `maxFindings` returning `LIMIT_EXCEEDED`.
    - Uncaught `NullPointerException` trapped returning `EXECUTION_ERROR`.
    - Cooperative cancellation aborts execution cleanly.
    - Hostile path traversal in manifests rejected with `PLUGIN_PATH_UNSAFE`.
    - Secret redaction masking verified in JSON and Markdown report exports.
    - Concurrent multi-threaded execution safety verified across 8 parallel threads.
  - `EmbedraPluginIntegrationTest`: Real-Ghidra integration test executing a regex flag plugin on a live program database, verifying bookmark creation, options persistence, and `GhidraFindingBookmarkSynchronizer` extraction.

## Scope and Invariants

- Bounded execution: Strictly enforced wall-time limits, finding count caps, input bounds, and cooperative cancellation.
- Zero secret leaking: Unmasked secrets never emitted in plain text in report exports by default (AN-008).
- Error containment: Rogue or hostile plugins cannot crash Ghidra, corrupt state, or hang analysis threads.
- Non-destructive: Does not alter or overwrite existing user symbols, comments, or program database structures.
- Pure/Adapter separation: Pure plugin domain models and runner stay strictly separated from Ghidra APIs (`ArchitectureBoundaryTest` verified).
