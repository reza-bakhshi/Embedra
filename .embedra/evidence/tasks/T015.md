## Implementation

- `EspApplicationImageLoader` detects by validated bytes rather than filename,
  offers only the exact ESP32-S3 Xtensa language/compiler pair, parses through
  the T011 bounded parser, and maps through the same provider/mapper path.
- `EspApplicationImageMapper` preflights chip support, program language,
  segment classifications, complete address ranges, existing block conflicts,
  and entry validity before mutation.
- One rollback-by-default transaction creates exact initialized blocks,
  applies provider permissions, preserves existing primary symbols, creates a
  deterministic imported `entry` label only when absent, adds the external
  entry point, and commits only after every operation succeeds.
- Checked failures use stable diagnostics for unsupported target, language
  mismatch, conflict, mapping failure, and entry rejection.
- `EspImportReport` and per-segment records retain committed device,
  language/compiler, encoded addresses, source ranges, permissions, and entry.
- Integration tests share the existing fixture resources without embedding
  repository paths or duplicating binaries.
