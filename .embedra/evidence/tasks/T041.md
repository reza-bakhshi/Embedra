## Scope and invariants

- The pure/adapter boundary holds: `Stm32CoreException`, `Stm32VectorPlan`, and
  `Stm32VectorPlanner` live under `targets`; Ghidra mutation stays in
  `Stm32VectorLabelApplicator`.
- T039 `memory-plans.json` (SHA-256
  `00def2817ba0660644a4bc6cea3ffb756e11aff4d7236a466f82de838c280c66`), the T040
  device-data packs, the applicability artifact (`be795ab0...`), and the
  WB15/WB55 non-secure SRAM2 limitation are unchanged.
- No vector address, handler name, interrupt number, or exact-part
  compatibility is invented. Family and wildcard inference remain forbidden.
- Core exceptions are always distinguishable from device IRQs. A conditional or
  variant-dependent interrupt list, an unconfirmed table, or an unknown base
  produces an explicit diagnostic and applies nothing.
- User symbols, functions, data, instructions, and comments are preserved;
  application is one rollback-capable transaction and is idempotent. Receipt
  addresses are retained so a deleted or renamed artifact is never resurrected.

## Implemented model

### Explicit core-exception table

`Stm32CoreException` is a nine-entry explicit table with canonical names,
negative CMSIS numbers, and Cortex-M slot math (`slot = 16 + number`):
`NonMaskableInt`, `HardFault`, `MemManage`, `BusFault`, `UsageFault`, `SVCall`,
`DebugMonitor`, `PendSV`, and `SysTick`. Reset is carried as the architectural
constant `Reset` (CMSIS `-15`, slot 1) rather than a fabricated enum value.
An exact part's applicability comes from its pinned interrupt list, so a reduced
Armv6-M core never gains an exception it does not implement. Standard exceptions
present in the table but absent from a part's pinned list stay reserved, and a
negative pinned exception the table does not list (for example `SecureFault_IRQn`
on selected TrustZone parts) is preserved with its pinned name and an
`UNLISTED_CORE_EXCEPTION` diagnostic.

### Confirmed vector plan

`Stm32VectorPlanner.plan` is pure. Given a confirmed 16+-word table and an
explicit image base/length, it emits one `Slot` per reset, core-exception,
reserved, stack-pointer, and pinned device IRQ slot. Handler addresses resolve
only to in-image Thumb targets; zero, non-Thumb, out-of-image, and slot-unmapped
words stay explicit with no fabricated function. Reserved words retain their raw
value and no name. Malformed input (truncated core table, unaligned table,
invalid range, duplicate or out-of-range pinned numbers/names) fails closed with
an `IllegalArgumentException`. A non-applicable interrupt list returns an
explicit non-applicable plan instead of guessing. `flashImageRange` makes the
T039 linkage explicit by deriving the confirmed image base/length from a
validated memory plan's FLASH region; a part with no validated flash region
fails closed, and the applicator has an overload that composes the plan instead
of a caller-supplied range.

### Ghidra application

`Stm32VectorLabelApplicator.apply` verifies the mapped table words against the
T037 candidate, reads the bounded confirmed words for every exact-part interrupt
slot, plans names/addresses purely, and inside one rollback-capable transaction:
creates or confirms primitive 32-bit vector words; creates qualified `IMPORTED`
labels; creates reset/core/device handler functions; and records provenance
(exact part, table address, source SHA-256, confirmation method, slot/resolved/
created/aliased counts, and retained created-address receipts). Existing user
functions, symbols, data, instructions, and comments are preserved with
deterministic `FUNCTION_PRESERVED`, `DATA_PRESERVED`, `NAME_CONFLICT`,
`UNRESOLVED_HANDLER`, `UNMAPPED_HANDLER`, and `ALIASED` conflicts. Reapplication
creates nothing new, and a deleted or renamed artifact stays absent
(`PRESERVED_ABSENT`) because receipt addresses/tokens are retained.

### Exact-part binding hardening (2026-10-02)

An independent review found that the adapter accepted any exact-part interrupt
entry without binding it to the program. `apply` now reads the exact part
recorded by the raw-import, SVD, interrupt, and vector-label provenance
namespaces and fails closed with `PACK_INCOMPATIBLE` when it disagrees with the
interrupt entry. The T040 applicator gained the same program-level check. Both
have regressions. The pure planner, names, addresses, and preserved-artifact
behavior are unchanged. See `.embedra/evidence/tasks/T039-T041-hardening.md`.

## Preserved boundaries and limitations

- T039 memory plans and the T040 device-data packs are not modified.
- All 53 curated parts remain `PLANNED`; T041 promotes no support state.
- Handler labels use the exact part's pinned interrupt names and the explicit
  core-exception names; no ST startup-style `_Handler` renaming is invented.
- Application requires an explicit T037 confirmation and image range. An image
  whose table is shorter than the exact part's pinned interrupt list fails
  closed rather than guessing unmapped vectors.
- "Core exception structures" is implemented as the explicit architectural table
  applied as qualified labels/functions and provenance; no new Ghidra struct
  data type is created over the T037 primitive words.
