# T082 Evidence — Refactor ESP Partition Discovery and Workspace Planner Behind Pure Flash-Layout Provider Contract

## Status

`COMPLETE` on 2026-10-13. T082 refactors the existing ESP32-S3 partition discovery and
workspace planner behind a pure, decoupled flash-layout provider contract. All hardcoded
S3 chip ID (`ESP32_S3_CHIP_ID = 9`), bootloader starting offset (`0`), and layout assumptions
are removed from shared discovery and planning code paths. Bounded partition scans are now
constrained by layout profile parameters (`[minPartitionTableOffset, maxPartitionTableOffset]`),
and target-specific image validation is delegated directly to layout providers. Bit-for-bit
backward compatibility and canonical S3 reports and snapshots are fully preserved.

## 1. Deliverables

1. **Pure Flash Layout Provider Model**:
   - `EspFlashLayoutProfile` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/EspFlashLayoutProfile.java`):
     - Immutable record specifying series name, chip ID, display name, ISA (`EspCpuIsa`),
       Ghidra language/compiler spec IDs, bootloader offset, partition table offset bounds
       (`defaultPartitionTableOffset`, `minPartitionTableOffset`, `maxPartitionTableOffset`),
       MMU page size, max supported flash size, and authoritative reference source facts.
     - Enforces invariant validation on offset alignment and bounds.
   - `EspFlashLayoutProvider` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/EspFlashLayoutProvider.java`):
     - Pure interface providing `providerId()`, `profile()`, default accessors (`chipId()`,
       `bootloaderOffset()`, `defaultPartitionTableOffset()`), offset validators
       (`isValidBootloaderOffset()`, `isValidPartitionTableOffset()`), and image validators
       (`validateBootloader()`, `validateApplication()`).
   - `Esp32S3FlashLayoutProvider` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/Esp32S3FlashLayoutProvider.java`):
     - Concrete implementation for ESP32-S3 (chip ID 9, bootloader at 0, partition table at `0x8000`,
       MMU page size 64 KiB, max flash 16 MiB).
     - Validates chip ID matches 9 for bootloader and application images with `DiagnosticCode.ESP_CHIP_MISMATCH`.
   - `EspFlashLayoutRegistry` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/layout/EspFlashLayoutRegistry.java`):
     - Thread-safe registry supporting lookups by chip ID and series name.

2. **Decoupled Shared Discovery and Planning Paths**:
   - `EspPartitionTableDiscovery` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/EspPartitionTableDiscovery.java`):
     - Added bounded `discover(byte[] flash, long defaultOffset, long minOffset, long maxOffset, ParserLimits limits, CancellationToken cancellation)` overload.
     - Scanning loop is bounded within `[scanStart, scanLimit]` rather than scanning unconstrained from 0.
   - `EspFullFlashWorkspacePlanner` (`src/main/java/io/github/rezabakhshi/embedra/formats/esp/EspFullFlashWorkspacePlanner.java`):
     - Removed static `ESP32_S3_CHIP_ID = 9` constant.
     - Added `plan(byte[] flash, EspFlashLayoutProvider provider, ParserLimits limits, CancellationToken cancellation)`.
     - Preserved public overload `plan(byte[] flash, ParserLimits limits, CancellationToken cancellation)` which resolves the target provider dynamically from candidate bootloader headers (`0x0000` or `0x1000`) or defaults cleanly to `Esp32S3FlashLayoutProvider.INSTANCE`.
     - Bootloader start offset is obtained from `provider.bootloaderOffset()` rather than hardcoded 0.
     - Image extraction uses `provider.chipId()` and calls `provider.validateBootloader()` / `provider.validateApplication()`.

3. **Automated Verification**:
   - `EspFlashLayoutProviderTest` (`src/test/java/io/github/rezabakhshi/embedra/formats/esp/layout/EspFlashLayoutProviderTest.java`):
     - Tests profile invariant validation and bounds checking.
     - Tests target offset validation and chip ID mismatch error handling.
     - Tests registry resolution by chip ID and series name.
   - `EspFullFlashWorkspacePlannerTest`:
     - All existing full-flash workspace tests pass without modification, confirming bit-for-bit canonical report and program strategy preservation.
