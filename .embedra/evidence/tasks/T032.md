# T032 Evidence — STM32 catalog generation

## Status

`IN_PROGRESS` on 2026-09-28. The acceptance boundary is defined in ADR 0026.
No T032 completion or STM32 firmware support claim is made.

## First source-ingestion slice

- Pinned ST `STM32_open_pin_data` BSD-3-Clause revision
  `7d1f1514ed5583ec5007ad91236b4e1d377295b1`.
- Deterministic, offline, derived source-facts snapshot: 2,240 MCU/MPU ST
  reference records, including package/memory alternatives, 230 records with
  more than one declared core, and per-file SHA-256 digests.
- Bounded generator, malformed/DTD/entity/size/cancellation tests, and
  scheduled/manual official-source drift workflow.
- Known gaps: exact orderable suffixes and memory-to-suffix pairing,
  lifecycle, DBGMCU IDs, complete heterogeneous/wireless topology, exact
  interrupt vectors, and CMSIS-SVD transformation mappings. These block T032.

## Remaining acceptance work

Reconcile with pinned authoritative ST/CMSIS sources for every available
MCU/MPU part; validate completeness, licensing, and redistribution; run all
required verification and two-build reproducibility before marking complete.

## CMSIS source reconciliation checkpoint

27 ST CMSIS Device repositories were pinned at exact Git revisions and checked
for Apache-2.0 licenses. A bounded generator indexed 377 IRQ-bearing headers
with per-header SHA-256 and core suffixes. Of 2,240 ST references, 1,906 map
to one nonconditional header, 164 to multiple nonconditional variants, 44 to
conditional IRQ definitions needing review, and 126 remain unmatched. MP2
CA35, CM33, and CM0 headers are kept separate. Five Python tests cover matching,
IRQ parsing, conditional status, malformed input, limits, and snapshot digest.
This is a further T032 slice, not completion.

## SVD rule-index checkpoint

196 ST-authored Apache-2.0 SVD files were indexed from a pinned third-party
transport with per-file SHA-256 and transformation-feature counts. Reference
mapping yielded 1,641 single candidates, 47 core-specific variants, 37
multiple candidates, and 515 unresolved references. Four Python tests cover
feature extraction, malformed/DTD rejection, matching, and snapshot integrity.
The transport and exact-device applicability remain explicit limitations.

## Exact C5 and pack-license checkpoint

The ST pack index exposed a newer C5 DFP absent from the 2,240-record open pin
snapshot. ST's BSD-3-Clause GitHub C5 DFP at
`a5f65bc64535cfa723e9d25f58d7ce23d0937aed` yielded 157 unique exact
orderable parts, three device-ID groups, package/memory facts, and nine
Apache-2.0 SVD identities with IRQs. A bounded generator and four Python tests
cover exact-variant integrity, memory/package/ID inheritance, malformed/DTD,
and snapshot digest. Lifecycle remains unknown.

Other ST pack-server DFP archives inspected used SLA0044 rev 6 with a
ST-processing-unit use restriction. They were excluded from committed data.
The Open-CMSIS-Pack F0 source examined here was redistributable but listed
`x` reference patterns rather than complete orderable suffixes. This source
boundary blocks full T032 exact-part and lifecycle acceptance.
