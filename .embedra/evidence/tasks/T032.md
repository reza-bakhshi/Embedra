## Status

`IN_PROGRESS` on 2026-09-29. The revised curated acceptance boundary is defined in ADR 0026.
No T032 completion or STM32 firmware support claim is made.

## Curated scope amendment (2026-09-29)

The maintainer replaced all-ST-MCU/MPU coverage with a finite, reviewable
catalog of commonly used exact parts. Initial target family: `STM32F103`.
Initial exact orderable parts: `STM32F103C8T6` (LQFP48, 64 KiB flash),
`STM32F103CBT6` (LQFP48, 128 KiB), and `STM32F103RBT6` (LQFP64, 128 KiB).
These are separate identities; `STM32F103` and the ST reference pattern
`STM32F103C(8-B)Tx` are never exact-part aliases. This selection is the entire
first T032 acceptance set. Other families and suffixes require explicit review.

Selection evidence: ST lists the exact C8, CB, and RB codes as active/orderable
on its [C8](https://www.st.com/en/microcontrollers-microprocessors/stm32f103c8),
[CB](https://www.st.com/en/microcontrollers-microprocessors/stm32f103cb), and
[RB](https://www.st.com/en/microcontrollers-microprocessors/stm32f103rb) product
pages. The [ST online store](https://estore.st.com/en/products/microcontrollers-microprocessors/stm32-32-bit-arm-174-cortex-174-mcus/stm32-mainstream-mcus/stm32f1-series/stm32f103/stm32f103rb.html)
listed RBT6 in stock when reviewed. Common use is supported by the
[Blue Pill entries](https://github.com/stm32duino/Arduino_Core_STM32/blob/main/README.md)
for F103C8/CB and ST's BSD-3-Clause
[NUCLEO-F103RB example](https://github.com/STMicroelectronics/STM32CubeF1/blob/c7656f1fee178058be2f8ebfc8df9eaf91dc565e/Projects/STM32F103RB-Nucleo/Examples/UART/UART_TwoBoards_ComDMA/readme.txt)
naming RBT6. Web pages justify curation and drift review; shipped technical
facts must come from the redistributable pinned ST pin data and Apache-2.0
CMSIS headers. Unavailable lifecycle/device-ID/SVD facts must stay explicit.

## Curated implementation checkpoint

`catalogs/stm32/2026-09-29/selection.json` is the reviewed three-part allowlist.
The bounded offline generator (`scripts/generate-stm32-curated-catalog.py`)
accepts only those three complete names, checks their distinct package,
flash-code, flash size, and RAM against pinned BSD-3-Clause ST reference
records, and binds their 52 IRQ entries to the pinned Apache-2.0
`stm32f103xb.h` header. The snapshot is deterministic and digest-stamped.
It records `UNKNOWN` lifecycle/device-ID/security and `UNMAPPED` exact SVD
applicability, rather than inheriting unsupported claims. All three support
states are `PLANNED`.

The extension package includes only the curated 2026-09-29 snapshot and
selection; the previous broad 2026-09-28 reference, IRQ, SVD, and C5 indexes
remain repository evidence and are excluded from the ZIP. Offline negative
tests reject family names, wildcard/suffix changes, duplicate entries,
package/flash mismatches, oversized inputs, and source/CMSIS provenance
mismatch. The scheduled/manual drift workflow checks current public Blue Pill
and NUCLEO board-use evidence and the existing ST pin/CMSIS upstream checks
continue to flag technical-source changes. Product-page orderability was
reviewed manually; direct ST page retrieval timed out from this environment.

## Local STM32CubeMX database audit

The user's local `/home/rez0x61/STM32CubeMX/db` installation has package
database revision `DB.6.0.181`. Its Finder archive
`db/plugins/mcufinder/mcu/cube-finder-db.zip` is a 43,554,792-byte ZIP with
SHA-256 `9b5a52038e1dbbda98aaa36e370bc19c866db3b187af9add22147a3f2300e076`.

RAM, core, die-ID, package, and security attributes.

The installed `help/software_license_agreement.pdf` has SHA-256
`6f977d32b83f2551c97dda96be939764eb8b17021076c0adefb2d8b`.

processing-unit restriction for the software package and derivatives. No
separate license for the Finder SQLite database was found in its directory or
ZIP. No source
rows, derived catalog, or database bytes were copied into the repository.
The aggregate audit establishes that CubeMX can help validate coverage, but
does not establish redistribution rights for Embedra's shipped host-side
catalog. T032 remains `IN_PROGRESS` pending explicit permission or another
licensed exact-part/lifecycle source.

## Redistributable source-seeking checkpoint

A refreshed GitHub organization search (`org:STMicroelectronics` matching `dfp`)
still returns only the BSD-3-Clause `stm32c5xx-dfp` repository as an
exact-part-bearing ST DFP. `STM32CubeU5-V2-Preview` carries the `dfp` topic but
publishes no permissive exact-part source. A new scheduled/manual job
`discover-new-st-dfp-sources` in `.github/workflows/stm32-catalog-drift.yml`
fetches the ST repository listing and runs
`scripts/discover-stm32-dfp-sources.py`, which flags any new STM32 `*-dfp`
repository for license review. Offline tests
(`test_discover_stm32_dfp_sources.py`, 5 cases) cover known/new detection, the
case-insensitive allowlist, `items`-wrapped listings, determinism, and malformed
listings. A live run against the GitHub API reported the source set unchanged.

The refreshed search confirmed the same boundary as commit `88dd908`: no
redistributable lifecycle-plus-exact-part source exists for the remaining
series. T032 needs either written ST permission to redistribute derived
exact-part/lifecycle facts or a spec amendment accepting a default-off,
user-local catalog built from the user's licensed CubeMX install (mirroring the
T026A pilot). No such pack is generated, committed, or shipped, and no exact
suffix or lifecycle state was invented.
