# T026A — ESP32-S3 ESP-IDF Function ID pilot

## Status

`COMPLETE` — committed T026A pilot and evidence; T027 remains next.

## Objective

Create a reproducible, evidence-backed ESP32-S3 ESP-IDF Function ID pilot that
names matching stripped ESP-IDF functions through an explicit opt-in path with
visible target/version/toolchain/configuration/optimization evidence and
user-name preservation. No claim that arbitrary stripped application functions
or every ESP-IDF version can be identified.

## Ghidra 12.1.3 findings recorded by this pilot

- `FidFile.canProcessLanguage` stores supported languages in a
  `ProcessorSizeComparator` set that ignores the language variant, so any
  Xtensa little-endian 32-bit library is *applicable* to
  `Xtensa:LE:32:esp32s3` programs. Applicability is not match validity; the
  Embedra run gate requires a variant-exact program, descriptor, and library
  record match (asserted by `genericVariantLibraryRefusedDespiteGhidraFamily
  Applicability`).
- `FidFile` computes its supported-language cache on first open, so a database
  created or populated in the same session can hold a stale empty set; the
  Embedra run path re-attaches once (preserving pre-existing user attachments)
  before executing.
- Ghidra's Function ID analyzer prints only a debug message when no library
  applies; Embedra status therefore comes from its own deterministic program
  options, never from the analyzer list.
- `.fidb` records use time-based `UniversalIdGenerator` ids: regeneration is
  content-equivalent but not byte-reproducible. The shipped database is a
  committed artifact with a recorded digest; this limitation is documented in
  ADR 0021.
- Headless ingest must run on a saved program (two-phase analyzeHeadless:
  import/analyze with FID and Library ID disabled, then `-process -noanalysis`
  ingest), matching the shipped `FunctionIDHeadlessPrescript` guidance.

## Completion and handoff

T026A is complete. The FID analyzer remains explicitly opt-in and disabled by
default. The pilot is limited to the recorded v6.0 reference identity and
matching functions; it makes no general stripped-application or cross-version
claim. T027 is the next task; T064 remains unstarted.
