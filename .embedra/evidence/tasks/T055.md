# T055 Evidence — Separate PIO discovery/disassembly, GUI/headless equivalence, and RP malformed-input fuzzing

## Status

`COMPLETE` on 2026-10-03. T055 implements dedicated PIO discovery and disassembly, workflow equivalence between headless batch import and interactive GUI import, and deterministic malformed-input fuzzing across the RP2040 and RP2350/RP2354 families:
- Dedicated PIO Disassembler (`targets.rp.pio`):
  - Pure Java 16-bit instruction decoder without Ghidra dependencies (`RpPioDisassembler`, `RpPioInstruction`).
  - Supports all 9 PIO instructions: `JMP`, `WAIT`, `IN`, `OUT`, `PUSH`, `PULL`, `MOV`, `IRQ`, `SET` and all operand/condition variations.
  - PIO instructions are strictly never disassembled as ARM Thumb or RISC-V instructions (RP-009).
  - Explicit configuration uncertainty modeling (`RpPioConfig`): preserves wrap bounds and side-set bit count uncertainty when not explicitly configured.
- PIO Program Scanner (`RpPioScanner`):
  - Pure scanner for `pio_program_t` structures (instructions pointer, length 1..32, origin -1..31, wrap config) within flash segments.
  - Fallback heuristic scanner for unanchored PIO instruction loops, strictly skipping boot2 (first 256 bytes) and vector table apertures.
- Ghidra PIO Applicator (`ghidra.rp.pio.RpPioApplicator`):
  - In a single transaction, annotates discovered PIO programs with `Embedra Disassembled PIO Program` bookmarks.
  - Emits comprehensive Plate comments with program name, length, origin, wrap target/wrap bounds, and side-set bit count.
  - Emits `[PIO] <instruction>` EOL comments and clears any accidental CPU code units by creating 16-bit WORD data units.
  - Registers PIO block apertures (`pio0`, `pio1` on RP2040; `pio0`, `pio1`, `pio2` on RP2350) and program options (`Embedra RP PIO`).
- GUI / Headless Workflow Equivalence (`RpWorkflowEquivalenceTest`):
  - Verified byte-for-byte, symbol-for-symbol, option-for-option, and bookmark-for-bookmark equivalence between headless batch import (`HeadlessLoadedProgram`) and interactive GUI import (`Loaded<Program>`) across:
    - RP2040 (`rp2040-pico-blinky.uf2`, ARMv6-M)
    - RP2350 ARM Secure (`rp2350-arm-pico2.uf2`, ARMv8-M Cortex-M33)
    - RP2350 RISC-V (`rp2350-riscv-pico2.uf2`, Hazard3 RV32IMAC)
- Deterministic Malformed-Input Fuzz Campaign (`RpDeterministicMalformedFuzzTest`):
  - Fixed-seed 300-case mutation test campaign:
    - 100 UF2 block mutations (corrupted magics, truncated blocks, invalid block numbers, conflicting family IDs).
    - 100 RP2040 boot2 mutations (corrupted CRC-32, truncated vectors, out-of-range stack pointers).
    - 100 RP2350 IMAGE_DEF block mutations (corrupted start/end magics, unknown item types, truncated pointers).
  - Verifies that all malformed inputs fail closed with appropriate `DiagnosticCode` (`CORRUPTED_RECORD`, `TRUNCATED_RECORD`, `INVALID_CHECKSUM`, `RP_BOOT_METADATA_INVALID`, etc.) without uncaught runtime exceptions or memory leaks.
- Support States: All silicon records and board profiles retain `PLANNED` state per RP-002 and STM-019.

## Scope and Invariants

- RP-009: PIO instructions are disassembled in a dedicated PIO view and never as ARM Thumb or RISC-V code.
- Pure/Adapter separation: `targets.rp.pio` remains pure Java with zero Ghidra API dependencies.
- Retain side-set and wrap uncertainty when unconfigured.
- Fail closed with typed `DiagnosticException` on malformed inputs under `ParserLimits` and `CancellationToken`.
- All RP silicon and board records retain `PLANNED` state.
