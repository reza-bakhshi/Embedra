# T069 Evidence — Idempotency and Preservation of User-Created Ghidra State Across Import and Enrichment Reruns

## Status

`COMPLETE` on 2026-10-10. T069 delivers the comprehensive real-Ghidra proof suite validating:
- **CORE-015 (Idempotency)**: Re-running importers or enrichments with identical inputs MUST be idempotent: no duplicate blocks, labels, functions, bookmarks, types, or findings.
- **CORE-016 (User State Preservation)**: User-created names, comments, types, bookmarks, and manual memory edits MUST NOT be silently overwritten; conflicts require a deterministic merge policy.

## 1. Test Suite Architecture

Located in `src/integrationTest/java/io/github/rezabakhshi/embedra/ghidra/state/GhidraStateIdempotencyIntegrationTest.java`:

- **Real Ghidra Program Environment**:
  - Initializes Ghidra 12.1.3 runtime in a headless transactional test harness.
  - Constructs ARM Cortex-M 32-bit little-endian flash memory blocks (`0x08000000`, 64 KB).

- **Injected User State Before Any Analysis**:
  1. **User Symbols**: `user_security_checkpoint` (`SourceType.USER_DEFINED`) created at `0x08000100`.
  2. **User Comments**: Both EOL (`USER_CRITICAL_EOL_COMMENT`) and PRE (`USER_CRITICAL_PRE_COMMENT`) at `0x08000200`.
  3. **User Bookmarks**: Category `"User Note Category"`, text `"Custom Analyst Hypothesis"` (`BookmarkType.NOTE`) at `0x08000300`.
  4. **User Functions**: Custom function `user_crypto_decrypt_core` with defined address range and `SourceType.USER_DEFINED` at `0x08000400`.
  5. **User Data Types**: Custom struct `CustomUserStruct` (`field_magic`, `field_status`) applied via `DataUtilities.createData` at `0x08000500`.
  6. **Manual Byte Edits**: User edited memory bytes `0xDEADBEEF` at `0x08000600`.

- **Comprehensive Multi-Applicator Enrichment Executions**:
  - `GhidraSecurityLeadApplicator`: Password comparison & debug shell leads (overlapping user comments to test non-destructive merging).
  - `GhidraCryptoApplicator`: AES S-Box table finding.
  - `GhidraStringApplicator`: Static literals and recovered stack strings.
  - `GhidraCtfApplicator`: Flag findings with secret masking.
  - `GhidraLoggingApplicator`: Diagnostic logging call sites and panic handlers.
  - `GhidraYaraApplicator`: Builtin ChaCha20 constant rule matching.
  - `Stm32SvdApplicator`: SVD peripheral registers and bitfield structs on `0x40010800` (GPIOA) overlapping user labels and comments.

## 2. Verification of Guarantees

### A. CORE-016 (User State Preservation)
- User symbol `user_security_checkpoint` remained unchanged as primary symbol with `SourceType.USER_DEFINED`.
- User comment `USER_CRITICAL_EOL_COMMENT` was strictly preserved as prefix; applicator annotation was safely concatenated via deterministic pipe ` | ` (`USER_CRITICAL_EOL_COMMENT | [Lead: Password / Token Comparison ...]`).
- User PRE comment `USER_CRITICAL_PRE_COMMENT` was completely untouched.
- User bookmark `User Note Category` / `Custom Analyst Hypothesis` remained intact.
- User function `user_crypto_decrypt_core` retained its custom name, body, and user-defined source.
- User data struct `CustomUserStruct` remained defined on the target memory range without overwrite.
- User byte edit `0xDEADBEEF` remained bit-for-bit unchanged.
- User label and comment on SVD peripheral registers (`0x40010800`) remained intact alongside imported peripheral registers.

### B. CORE-015 (Idempotency Across Enrichment Reruns)
- Executed Pass 2 and Pass 3 identical enrichment reruns across all applicators.
- **Bookmark Invariance**: Total bookmark count remained strictly identical across passes (Pass 1 = 9, Pass 2 = 9, Pass 3 = 9). Zero bookmark duplication.
- **Comment Invariance**: Comment strings remained strictly stable across rerun passes (no duplicate appended annotations).
- **Symbol & Block Invariance**: Zero new blocks, zero new symbols, and zero new data types created during reapplication (`report.createdBlocks().size() == 0`, `report.createdSymbols().size() == 0`).
